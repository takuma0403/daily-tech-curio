### <a id="card-1"></a>🆕 冷戦の置き土産が、ワインの嘘を暴く時計になった——ボムパルスの炭素14 〔move: 物理現象へのピギーバック / 領域: ワイルドカード(核物理・法科学) / レンズ: 無関係な2技術の組み合わせ〕

**事実**: 1945〜1963年に世界中で行われた大気圏内核実験で、大気中の放射性炭素14の濃度が自然存在比のほぼ2倍まで跳ね上がった。この「ボムパルス」は1963年の部分的核実験禁止条約後、海洋や生物圏に吸収されて指数関数的に減り続け、1年ごとにほぼ一意の濃度カーブを描いている。生きている間に大気中のCO2を取り込む植物や動物の体には、育った瞬間の大気の濃度がそのまま焼き付く。

**何ができる**: ブドウが育った年の大気C14濃度が分かっていれば、加速器質量分析計(AMS)でワイン中のエタノールのC14/C12比を測るだけで、ラベルの収穫年が本物かを1年以内、場合によっては数ヶ月単位の精度で判定できる。同じ理屈は、形成後は更新されない歯のエナメル質から生年や死亡時期を推定する法医学、麻薬の精製時期特定、絵画キャンバスの製造年判定にも横展開できる。

**技術の魅力**: 放射性炭素年代測定は本来「何千年も前の遺物」を測るための道具で、数十年単位の誤差は誰も気にしない用途だった。ところがボムパルスという人為的な急上昇・急降下のおかげで、直近数十年という短いスケールでも年単位の精度が出るという逆転が起きている。核実験という一度きりの人類史的事件が、地球全体に同期した"タイムスタンプ"を無料でばら撒いてくれたようなものだ。

**本来どこで使われてるか**: オーストラリアの研究チームが2010年前後にこの手法をワイン鑑定に応用し、1958〜1997年のオーストラリア産赤ワイン20本の年代を1年以内の精度で言い当てることに成功した。中国の年代物白酒(バイジュウ)の真贋判定でも同じ手法が使われている。法医学分野では、身元不明遺体の歯のエナメル質からの生年推定や、死亡後経過時間の推定にも実用化されている。

### <a id="card-2"></a>🔍 耳で聞くだけで中間者を見抜く——ZRTPが検証を人間の声に丸投げする理由 〔move: 人間/身体をプロトコルの一部にする / 領域: セキュリティ/認証〕

**事実**: 暗号化された音声通話の多くは、通話開始時にディフィー・ヘルマン鍵交換で共通鍵を作る。だがこの交換には本質的な弱点があり、通信路の途中に割り込んだ攻撃者が両者それぞれと別々に鍵交換をして中間者攻撃(MITM)を成立させても、当事者は普通気づけない。認証局のような信頼済みの第三者を使わずにこれを検知する仕組みが、Phil Zimmermann考案・RFC 6189のZRTPにあるShort Authentication String(SAS)。

**何ができる**: 鍵交換の結果からハッシュを取り、それを「聞き間違えない単語」だけで構成したPGP Word List(NATOフォネティックコードの拡張版のようなもの)に変換して、通話中の両者の画面に2〜4語ずつ表示する。あとは電話越しにその単語をお互い読み上げて一致を確認するだけで、途中に割り込む攻撃者がいれば単語が食い違う。認証局も証明書も、通話の外の連絡手段すら要らない。

**技術の魅力**: 本来この手のMITM検知は公開鍵基盤(PKI)や、アプリの外での鍵確認(QRコードのスキャンなど)に頼るのが定石だが、ZRTPは「いままさに繋がっている音声チャネルそのもの」を検証チャネルとして使い回す。攻撃者は音声を中継することはできても、両者が読み上げる単語を自分の声で両方に一致させることは容易ではない——通話という体験そのものが認証の一部になっている非対称性が効いている。

**本来どこで使われてるか**: PGPの生みの親Phil ZimmermannがPKIに頼らないp2p暗号化通話のために設計し、暗号化通話サービスのSilent Circle、オープンソースSIPクライアントのLinphoneやJitsiが実装している。企業のPKIに頼れない相手同士(ジャーナリストと情報源など)がその場で安全性を確認できる手段として実運用されている。
出典: https://en.wikipedia.org/wiki/ZRTP / https://en.wikipedia.org/wiki/PGP_word_list

### <a id="card-3"></a>💡 JSを1行も使わずにパスワードを盗む——CSS属性セレクタが背負わされた密輸業 〔move: 仕様の目的外利用 / 領域: フロントエンド/グラフィックス〕

**事実**: CSSの属性セレクタ(`input[value^="a"]`のような書き方)は、本来フォーム部品の状態に応じて見た目を変えるための機能で、値の中身を"読む"ためのものではない。ところが`background-image: url(...)`と組み合わせると、セレクタが一致した瞬間にブラウザがその画像URLへ実際にHTTPリクエストを飛ばすという副作用が起きる。この副作用自体は仕様通りの正しい挙動であり、バグではない。

**何ができる**: パスワード欄やCSRFトークンの隠しinputに対して「値の先頭が'a'なら攻撃者サーバーの/aへ、'b'なら/bへ画像を取りに行け」というルールを1文字ずつ全パターン用意しておけば、どのリクエストが実際に飛んだかを攻撃者サーバーのアクセスログで見るだけで、値を1文字ずつ確定させ最終的に全文を復元できる。JavaScriptを一切実行させずにHTML/CSSインジェクションだけで完結する。

**技術の魅力**: 多くのサイトはContent-Security-Policyで`script-src`を厳しく絞ってXSSを封じても、`style-src`は緩いままにしがちで、「CSSはただの見た目だから安全」という思い込みが穴になる。本来ユーザー体験を良くするための宣言的なスタイル言語が、宣言した瞬間に外部へネットワークリクエストを飛ばせるという一点だけを使って、能動的なデータ持ち出しチャネルに化ける。受動的なはずの言語に抜け道が仕込まれている非対称性が効いている。

**本来どこで使われてるか**: PortSwiggerの研究チームが、JavaScriptインジェクションは防げてもHTML/CSSインジェクションが残ってしまうケースへの実証としてこの手法(Blind CSS Exfiltration)を公開し、`:has()`セレクタを使ったさらに踏み込んだ亜種も示している。実際のバグバウンティでもCSRFトークンやOAuthトークンの窃取に使われた報告があり、CSPの`style-src`設定を見直すきっかけになっている。
出典: https://portswigger.net/research/blind-css-exfiltration / https://portswigger.net/research/inline-style-exfiltration
