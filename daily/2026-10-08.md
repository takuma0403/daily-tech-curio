### <a id="card-1"></a>🆕 ポートが閉じたままなのに、1通のUDPで開く——Single Packet Authorization 〔move: 仕様の目的外利用 / 領域: セキュリティ/認証〕

**事実**: 普通のサーバーは `listen()` したポートに来る接続を受けるので、スキャンすれば「そこに居る」とバレる。Single Packet Authorization（SPA）の実装 fwknop は逆で、サーバー側のデーモンはどのポートも開かず、libpcap で NIC を流れるパケットを盗み聴きしているだけ。ファイアウォールは SSH などを全閉じにしておき、暗号化＋HMAC された「開けてくれ」の1パケットがワイヤ上を通り過ぎた瞬間だけ、その送信元IPへ iptables ルールを一時的に空ける。nmap から見れば最初から最後まで何も居ない。

**何ができる**: 自宅や VPS の SSH を、鍵を持つ人以外には「存在しない」状態にできる。ポートノッキングが「複数ポートを順番に叩く」合図（盗み見・再生に弱い）なのに対し、SPA は1パケットに暗号化された要求（開けるポート・時刻・乱数）を詰めるので再生されても弾ける。ボタンを1つ押すと UDP を1発だけ撃つ ESP32 を鍵束に付ければ、「物理ボタンが玄関の鍵」になる。受け側が `listen()` していないので、パケットの宛先が閉じたポートでも、受信を無視する宛先でも構わない。

**技術の魅力**: 「サービスを守る」ではなく「サービスが居ることを隠す」という発想の反転。認証が成功する前には攻撃対象そのものが存在しないので、未知の脆弱性（ゼロデイ）があってもスキャン経由では届かない。デーモンはパケットを“受け取る”のではなく“見る”だけ、というネットワーク層の抜け道が肝。一方で送信元IPは偽装できるため、IPではなく中身の暗号と再生防止で信用する設計になっている。

**本来どこで使われてるか**: 企業や個人のサーバー管理で、SSH や管理画面の公開を最小化する用途。fwknop は Linux ディストリビューション（Fedora・Debian）にパッケージ化されており、libpcap でパッシブに監視する設計がパッケージ説明にも明記されている。オープンソースの SPA 実装として、Zero Trust 系のネットワークアクセス制御（Software-Defined Perimeter）の源流の一つでもある。
出典: https://packages.fedoraproject.org/pkgs/fwknop/fwknop / https://mankier.com/package/fwknop

### <a id="card-2"></a>🔍 電波の「宛名欄」そのものを、テレメトリの封筒にする——WSPRと気球 〔move: 制約の極端化 / 領域: 無線/組み込み/ハードウェア〕

**事実**: WSPR（Weak Signal Propagation Reporter）は、アマチュア無線家が電波伝搬を測るために2分ごとに決まった短いメッセージを送る方式で、メッセージは「コールサイン・4桁グリッド・出力(dBm)」の3欄しかない。ところが世界中の受信局がこれを勝手に復調して公開データベースへ報告している。この「世界規模の無料受信網」に便乗して、3欄の中身を宛名ではなくデータとして使う人たちがいる。

**何ができる**: コールサイン欄の0・1・Qで始まる番号（ITUが割り当てない）を“チャネル番号”とみなし、グリッドの5〜6文字目に位置、出力欄に高度・電圧などを詰める。Traquito 方式では高度(20m刻み)・温度・電池電圧・速度・GPS有効を2通のWSPRに詰め、RP2040 のオンチップ温度センサーを使う。つまり送信機1個（数十mW）を気球に載せるだけで、受信局もサーバーも自前で持たずに、地球の裏側で誰かが拾った位置と電池電圧が公開DBに溜まる。出力欄を3dB刻みの高度に直接割り当てる単純版（高度÷300）もある。

**技術の魅力**: 制約が3欄・数十ビットしかないからこそ、「ビットをどう割り当てるか」が設計の全てになる。しかも運用者は一台も受信機を立てなくていい——他人が趣味で張った受信網が、あなたの気球のダウンリンクになる。トレードオフも率直で、温度が循環インデックスなので-45℃と45℃が区別できない、といった曖昧さを仕様の側が抱えている。

**本来どこで使われてるか**: 本来は短波〜超短波の電波が電離層でどこまで届くかの観測。実用中の用途は、QRP Labs の U4B 系やピコ気球の追跡で、低出力・小型・軽量で成層圏をほぼ周回する気球が実際にこの方式で追われている。
出典: https://traq6046.codeberg.page/pro/telemetry/basic/ / https://qrp-labs.com/u4b/u4bdecoding.html / https://klofas.com/blog/2021/picoballoon-launch-3/

### <a id="card-3"></a>💡 ハエトリソウは「2回目」まで撃たない——カルシウムの減衰で数える、植物のノイズ除去回路 〔move: 異分野の手法移植 / 領域: ワイルドカード(植物生理×センサー)〕

**事実**: ハエトリソウの葉は、感覚毛に1回触れただけでは閉じない。約30秒以内にもう一度触れられたときだけ閉じる。研究では、触れるたびに感覚毛の根元でカルシウム濃度が上がり、時間とともに減衰する“残り火”になっていると分かった。1回目の残りに2回目が積み上がって閾値を越えたときだけ捕獲が発動する。神経も脳もない植物が、減衰する量を使って「30秒以内に2回」を数えている。

**何ができる**: これをそのままセンサー側のイベント判定に写せる。リーキーバケット（時間とともに漏れるカウンタ）を1つ持ち、イベントごとに一定量足し、閾値を2回ぶんにしておく。ノイズ由来の単発スパイクは漏れて消え、短時間に連続した本物だけが発火する。ドア開閉、振動、PIR などの偽陽性が多いセンサーの前段で、スレッショルド1つ・状態変数1つ・タイマー無しで動く。「30秒」は漏れ率だけで決まるので、ミリ秒単位のタイムスタンプ配列を持たなくていい。

**技術の魅力**: 2回数える機構が、カウンタとタイマーの2部品ではなく、減衰する1つの物理量に畳まれているところが美しい。「何回起きたか」と「どれだけ最近か」を同時に表す状態が1個で済む。実装は1行（`x = x*decay + hit; fire = x > th`）で、サーバー不要でマイコン内に収まる。

**本来どこで使われてるか**: 本来は虫を捕らえるかどうかの判定。誤って雨粒などでは閉じず、獲物と確定したときだけ高コストな閉鎖を行うための仕組みで、獲物の消化を始める段階ではさらに複数回の刺激数まで数える。研究は Hedrich 氏らのヴュルツブルク大学の研究グループと、Hasebe 氏のグループの2020年の Nature Plants 論文で、カルシウム蛍光センサー入りの植物で可視化された。
出典: https://www.sciencenews.org/article/how-venus-flytraps-store-short-term-memories-prey/amp / https://www.biologie.uni-wuerzburg.de/en/aktuelles/detail/news/how-the-venus-flytrap-counts-1
