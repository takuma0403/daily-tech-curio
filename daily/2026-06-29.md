### <a id="card-1"></a>🎰 CSSだけで動く「数字ロールアップ計器」——@property がカウンターを乗っ取る 〔move: 仕様の目的外利用 / 領域: フロントエンド/グラフィックス〕

**事実**: CSS Houdini の `@property`（CSS Properties & Values API）は、カスタムプロパティに型情報を与えるために設計された仕様だ。`syntax: '<integer>'` と宣言した途端に、ブラウザはそのプロパティを「本物の整数」として扱う——CSSトランジションやアニメーションで線形補間が効くようになる。型未定のカスタムプロパティ（`--count: 0` など）は「文字列」なので、`transition: --count 2s` と書いても 0 から 100 に一瞬でジャンプするだけだ。そしてブラウザは補間計算をGPUにオフロードするため、JS setInterval で数値をインクリメントするより滑らかで省電力になる。

**何ができる**: `@property` で `--n` を `<integer>` として登録し、`@keyframes` で 0 から 100 に変化させる。これを CSS 標準の `counter-reset: n var(--n)` に食わせ、`::before { content: counter(n); }` で疑似要素に出力すると、純粋 CSS だけで "0→99" と数字がスムーズに繰り上がる表示が作れる。JavaScript はゼロ行、サーバーも不要。応用として、複数の要素に異なるアニメーション遅延をつければ、時計のような「桁ごとに独立して回転する」メーター表示を CSS だけで組み上げられる。さらに `@property` の `inherits: true` を使えば、親要素のアニメーション値が子要素に CSS 継承として流れ込み、連動する多段アニメーションをイベントハンドラなしで構成できる。

**技術の魅力**: `content` プロパティは文字列しか出力できないので、アニメーションした数値をそのままテキストとして表示できない——`counter()` という間接経路を経由することで数値→文字列変換を突き抜ける。これは「型システムを迂回するハック」ではなく、CSS の3つの独立した仕様（Properties & Values API / CSS Counters / Pseudo-elements）が偶然かみ合ったことで生まれた使い方だ。`@property` の設計者は「カウンター表示に使う」とは想定していなかったはずで、仕様の目的と実現できることの間にある隙間を埋めた応用になっている。

**本来どこで使われてるか**: `@property` の主目的は「デザイントークンの type-safe 化」だ。グラデーションの始点色を `<color>` として登録すれば、ホバー時に `transition` で色がぬるっと変わる——これが想定ユースケース。Chromium 85（2020年8月）で初実装、Firefox 128（2024年）・Safari 16.4（2023年）でも対応し、今やすべてのモダンブラウザで使える。CSS-Tricks の記事「Animating Number Counters」がこのカウンタートリックを広め、以降 UI コンポーネントライブラリがロールアップアニメーションを JS 不要で実装する定番手法になった。Adam Argyle（Google Chrome チーム）も `@property` の実験的応用として、グラデーション角度・色相回転・パーセント値など「以前はアニメーションできなかった CSS 値」を次々と動かすデモを公開し続けている。
出典: https://css-tricks.com/animating-number-counters/ / https://web.dev/articles/at-property

### <a id="card-2"></a>🧲 ビルの鉄筋が作る磁場の模様を"地図"にする——GPS ゼロの屋内測位 〔move: センサーの転用 / 領域: 無線·組み込み/ハードウェア〕

**事実**: 建物の中では地球磁場がコンクリートの鉄筋・エレベーターシャフト・鉄骨梁に歪められ、場所ごとに固有の「磁場フィンガープリント」が形成されている。スマートフォンのマグネトメーター（コンパス）が示す地磁気ベクトル（µT 単位の 3 軸値）は、同じフロア内でも廊下の角を曲がるだけで値が変化する。ブラウザからは Generic Sensor API の `Magnetometer` や `AbsoluteOrientationSensor` でこのデータを読める（HTTPS + ユーザー許可が必要）。この磁場パターンは WiFi 電波や GPS と違い受動的に常時存在しており、インフラ投資なしに「ここ」を定義する指紋として機能する。

**何ができる**: あらかじめロボットや作業員がフロアを歩き回り、磁場ベクトルと座標をマッピングした「磁場フロアマップ」を作成（キャリブレーション）しておく。以降はスマートフォンが連続的に磁場ベクトルを測定し、パーティクルフィルタや k-NN でマップと照合してリアルタイムの位置を推定する。WiFi ビーコンも BLE タグも電源工事も一切不要。IndoorAtlas 社の商用実装では誤差 2m 以内を達成しており、既存インフラゼロでの屋内ナビゲーション・資産追跡・施設スタッフ管理に展開されている。

**技術の魅力**: マグネトメーターは「北を指す」ために搭載された。それを「いる場所を指す」ものに転用する逆転が効いている。WiFi 電波は時刻・負荷・干渉で変動し、BLE はタグの電池が切れれば沈黙するが、磁場フィンガープリントは建物の骨格から生まれているので電源不要で半永久的に安定する。センサー側（スマホ）は電波を一切放射しないため、完全受動的な位置確認が成立し、外部から傍受・追跡することができない。位置を「座標」ではなく「その場所にしか存在しない物理現象」で定義するという発想が、GPS の延長線上にない解法を生み出している。

**本来どこで使われてるか**: コンパスとしての用途（方位角）が主眼だったマグネトメーターを「位置センサー」に転用した研究は Microsoft Research や複数の大学チームが 2010 年代に論文発表した。それを商用に昇華したのがフィンランド・オウル大学からのスピンオフである IndoorAtlas 社（2012年創業）で、Apple Store・国際空港・ショッピングモールへの導入事例がある。IEEE/ACM の屋内測位コンペティション（IPIN Competition）では磁場単独方式が WiFi RSSI 方式に匹敵する精度を記録している。歩行者デッドレコニング（PDR）と組み合わせると磁場更新頻度が低い場面での精度落ちを補えることも実証されている。
出典: https://www.gpsworld.com/indooratlas-announces-geomagnetic-indoor-positioning-service/ / https://www.ncbi.nlm.nih.gov/pmc/articles/PMC6308508/

### <a id="card-3"></a>🐘 ブラウザタブの中で PostgreSQL が本当に走っている——PGlite という極端な実験 〔move: 制約の極端化 / 領域: データ/同期/ストレージ〕

**事実**: 2024年、ElectricSQL と Neon が共同で「PGlite」を公開した。PostgreSQL 16 のソースコードをそのまま Emscripten で WebAssembly にコンパイルしたもので、「Postgres をエミュレートした別実装」ではなく Postgres 本体が WASM で動いている。gzip 後わずか 3MB で、pgvector（ベクトル検索）や PostGIS（地理空間演算）拡張も同梱される。ブラウザでは IndexedDB または OPFS にデータを永続化でき、Node.js・Bun・Deno でも同じバイナリが動作する。以前の試みが「Linux VM を WASM で動かし、その中で Postgres を動かす」2段構えだったのに対し、PGlite は Linux 層を除去し Emscripten の WASI ラッパーで直接システムコールを処理した。

**何ができる**: サーバーなし・インターネット接続なし・インストールなしで、フル PostgreSQL SQL（CTE・ウィンドウ関数・再帰クエリ・全文検索・JSONB）をブラウザタブの中で実行できる。GeoJSON ファイルをドラッグ&ドロップして PostGIS 関数で面積計算・空間結合を行うオフライン GIS アプリ、pgvector を使ったセマンティック検索エンジンの完全クライアントサイド実装、Cypress テストでサーバーゼロのDB統合テストを回す——どれもサーバー費用ゼロで動く。ElectricSQL 自身は PGlite をローカルファースト同期の受信端として使い、サーバーサイド Postgres の変更差分をリアルタイムでブラウザ内 PGlite に配信するアーキテクチャを構築している。

**技術の魅力**: 「制約の極端化：サーバー 0、DB は妥協せず PostgreSQL 本体」を真剣に突き詰めた結果として生まれた。DB を軽量な SQLite に置き換えるのではなく、本物の Postgres をそのまま持ち込むという選択は、SQL 互換性・拡張エコシステム・ORM サポートをそのまま継承できる点で別種の解を開く。「ブラウザでも本番と全く同じ SQL が動く」という性質は、フロントエンド開発者のテストループを根本的に変える——CI サーバー料金が消え、オフラインでも DB テストが完結する。

**本来どこで使われてるか**: PGlite は 2024年8月に Hacker News で公開され HN 1位を獲得した（スコア 1200+）。Neon はサーバーレスブランチ機能のテスト環境として、ElectricSQL はリアルタイム差分同期クライアントとして実戦投入している。コミュニティでは pgvector 内蔵を活かし、WebLLM（ブラウザ内 LLM 推論）で生成したテキスト埋め込みを PGlite にローカル保存・類似検索するプロトタイプが多数作られている。また Cypress・Vitest の統合テストで「Docker なし・マイグレーション込みの本物の Postgres テスト」を CI 上で実現する事例も増えている。
出典: https://pglite.dev/ / https://github.com/electric-sql/pglite / https://news.ycombinator.com/item?id=41224689
