### <a id="card-1"></a>🆕 「計算した」ことを切手にして、誰の許可もなく手紙を送る——Hashcashを“発行元なしの切手”にする 〔move: 仕様の目的外利用 / 領域: セキュリティ/認証〕

**事実**: Hashcashは1997年にAdam Backが提案した仕組みで、「宛先・日付・乱数」を含む文字列のSHA-1ハッシュの先頭が、指定ビット数ぶん0になるまでカウンタを回して探したものを“スタンプ”とする。探すのは総当たりで重いが、検証はハッシュ1回で済む。メールではX-Hashcashヘッダーに載せ、スパム対策に使うことを想定していた。見落とされがちなのは、スタンプの発行に認証局も口座も要らず、**計算した事実だけが証拠になる**点。

**何ができる**: 受信側は自分宛ての文字列かどうかと先頭ビットを確かめるだけで、サーバーもアカウントも使わずに「この送信者は一定の計算コストを払った」と判定できる。たとえば問い合わせフォーム代わりのQRコードや、静的サイトのメール受付に「22ビットのスタンプ付きでないと開封しない」ルールを置けば、1通ごとの送信コストを人間には数秒、大量送信者には現実的でない量にできる。難易度ビット数は受信者が自由に決められる。

**技術の魅力**: 信頼を「誰が保証したか」から「どれだけ手間をかけたか」に置き換える非対称性が核。コストの上げ下げが1ビット単位で、検証は常に軽い。しかも宛先を文字列に含めるので、他人宛てのスタンプの使い回しは効かない。

**本来どこで使われてるか**: 本来はメールのスパム対策で、コンテンツフィルターやブラックリストで弾かれる送信者がスタンプで通りやすくなるよう設計された。Debianなどにhashcashコマンドが配布されている。同じ発想（部分ハッシュ衝突の探索）は後にビットコインのマイニングの着想源として引用された。
出典: https://en.wikipedia.org/wiki/Hashcash / https://manpages.ubuntu.com/manpages/focal/man1/hashcash.1.html / https://diswww.mit.edu/bloom-picayune/crypto/15960

### <a id="card-2"></a>🔍 ファイルを1バイトずつ滑らせて「同じ塊」を探す——rsyncのローリングチェックサムを“差分転送の目”にする 〔move: 異分野の手法移植 / 領域: データ/同期/ストレージ〕

**事実**: rsyncは、受信側の古いファイルを固定長ブロックに切り、各ブロックに32bitの弱いチェックサムと強いハッシュ(MD4)を付けて送信側へ渡す。送信側は自分のファイルを**1バイトずつずらしながら**弱いチェックサムを調べるが、窓が1バイト進むたびに古いバイトを引き、新しいバイトを足すだけで更新できる(Adler-32に着想を得た定数時間の更新式)。弱い方が一致した時だけ強いハッシュで確かめる。

**何ができる**: 「ブロックの境目がずれていても同じ中身を見つけられる」ので、先頭に1行足されただけのファイルでも、残りはほぼ全部“既にある”と判定できる。これを回線の細い場面(LoRaやシリアル経由のファームウェア更新、USBメモリの手渡し運用)に持ち込めば、ネットワークがなくても、受け取り側が持つ旧版のブロック表を一度渡すだけで差分だけ作れる。サーバーなしで、2者が顔を合わせた時に完結する。

**技術の魅力**: 固定長の分割は挿入に弱いが、安い弱ハッシュで全オフセットを走査し、当たりだけ高価なハッシュで裏取りする二段構えが効く。“速いが誤りうる目”と“遅いが確実な目”を重ねる設計の見本。

**本来どこで使われてるか**: Andrew Tridgellらによるrsyncの転送アルゴリズム。ブロック長は500〜1000バイト程度が良いと技術報告に書かれている。バックアップやミラーリングで標準的に使われ、同系統の考えは差分アップデートやコンテンツ定義分割(CDC)にも広がっている。
出典: https://rsync.samba.org/tech_report/node3.html / https://mattmccutchen.net/rsync/rsync.git/blob/HEAD:/tech_report.tex

### <a id="card-3"></a>💡 インカの紐は、結び目で桁を数えるメモリだった——キープ(khipu)に10進数を結んで読む 〔move: 人間/身体をプロトコルの一部にする / 領域: ワイルドカード(歴史×記録媒体)〕

**事実**: キープ(quipu/khipu)は、インカが使った結び目の記録媒体で、主紐から垂れた多数の垂下紐に結び目を作る。結び目の**位置が桁**で、紐の端に近いほど1の位、離れるほど10・100の位になる。1は8の字結び、2〜9は単結びの回数、10の倍数は長結びなど、結び方でも値を分ける。確認できる現存品は700〜850点ほどとされ、数以外の意味(人名や品目)は未解読のまま。

**何ができる**: 紐と指だけで、電源のない10進数ストレージが作れる。畑の収穫量、イベントの参加者数、工作の部品在庫を紐の結び目で残し、あとでスマホのカメラで結び目の位置を数えて読み取る、といった“ローテクなオフライン台帳”が試せる。紐を束ねれば、列(紐)×桁(位置)の表になるので、小さな表計算のように使える。

**技術の魅力**: 位取り記数を、文字も紙もインクも使わずに素材の物理配置だけで実現している点が痛快。さらに一度結べば誰かが解かない限り消えず、触れば指で読めるので、読み出しにデバイスが要らない。

**本来どこで使われてるか**: 16世紀までのアンデス地域で、税や物資の勘定、人口や家畜の記録に使われた。レランド・ロックが1920年代に、結び目の群が10進の桁を表すことを示した。Gary Urtonらが2002年から、世界各地の博物館のキープを集めた「Khipu Database」を構築し、約520点が登録されている。
出典: https://en.wikipedia.org/wiki/Quipu / https://www.sciencenews.org/article/knotted-strings-and-inca-accounts / https://grantome.com/grant/NSF/BCS-1111489

🔎 検索ワード: `Khipu Database Project Gary Urton` / `quipu decimal knots Leland Locke` / `khipu long knot figure-eight knot` / 「キープ インカ 結び目 数字」
