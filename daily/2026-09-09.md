### <a id="card-1"></a>🆕 1本の共有ピンが、名乗り出る順番まで勝手に決める——SMBus Alert Response Addressという配線任せの割り込みコントローラ 〔move: 制約の極端化 / 領域: 無線/組み込み/ハードウェア〕

**事実**: I2C/SMBusにぶら下がる多数のセンサー・PMIC・バッテリーゲージICは、割り込みを上げたいとき本来なら専用IRQピンを1本ずつホストへ配線したいところだが、ピン数節約のため複数チップで1本の共有オープンドレイン線 `SMBALERT#` を共用する。誰が割り込んだかを見分ける専用の割り込みコントローラは存在しない。代わりにSMBus仕様は「Alert Response Address（ARA, 0001 100xb = 0x0C）」という予約アドレスを用意し、ホストがそこへ1バイトreadを投げると、`SMBALERT#`を下げている全チップが自分の7bitアドレスを一斉に返答する。

**何ができる**: 複数チップが同時に応答しても壊れない。I2Cの標準アービトレーション（オープンドレインでは"0"が"1"に勝つワイヤードAND多数決）がそのままバス上で働くので、一番小さいアドレス値のチップだけが応答の最後まで生き残り、負けたチップは自然に沈黙する。つまり「誰が呼んだか」を判別する優先度エンコーダを、ソフトのポーリングでも専用ハードでもなく、電気的な多数決だけで実現している。負けたチップは`SMBALERT#`を下げたままなので、ホストはARAへのreadを勝者がいなくなるまで繰り返すだけで、共有1本の線から全員の名乗りを漏れなく回収できる。

**技術の魅力**: 普通、複数の発信源を1本の線に集約すると「誰が言ったか」の情報は消える。ここでは物理層のアービトレーションという本来ノイズ寄りの機構を、そのまま優先度つき名乗りプロトコルとして転用している。GPIO1本を節約するための倹約仕様が、結果的に組み込み側から「割り込みコントローラ」という別部品を丸ごと消し去っている、という副産物の大きさが効いている。

**本来どこで使われてるか**: PMIC・バッテリーフューエルゲージ・電流モニタICなど、ピン数に厳しい小型基板で標準的に使われる。TI/ADI製のバッテリー管理ICやINA226のようなパワーモニタは軒並み`SMBALERT#`とARAをサポートし、Linuxカーネルも`i2c-smbus alert`ドライバとして正式対応する。ノートPCやサーバーの電源管理サブシステムが、この仕組みで数十個のセンサー異常を1本の線から拾っている。
出典: https://smbus.org/specs/SMBus_3_1_20180319.pdf / https://www.ti.com/lit/an/slaa249b/slaa249b.pdf / https://docs.kernel.org/i2c/smbus-protocol.html

### <a id="card-2"></a>🔍 自分の首を絞めるためだけに存在した仕様が、閉域網の"自爆スイッチ"として蘇る——HTTP Public Key Pinningという廃止済みの人質機能 〔move: レガシー/廃止予定機能の蘇生 / 領域: セキュリティ/認証〕

**事実**: HPKP（HTTP Public Key Pinning, RFC 7469）は、サイトが「今後このサイトに来る証明書は、あらかじめ宣言した公開鍵のどれかで署名されていなければならない」とレスポンスヘッダで宣言し、ブラウザにピン留めさせる仕組みだった。狙いはCAの不正発行への防御だったが、ピン情報の鍵を運営者自身が紛失したり、更新を怠ったまま証明書をローテーションすると、正規の証明書ですら拒否されてサイトごとユーザーを締め出す「RansomPKP」状態に陥る欠陥が露呈し、Chrome/Firefoxは2017〜18年に非推奨化・削除した。

**何ができる**: 廃止された理由そのもの——「間違えると自分を永久ロックアウトする」という性質——を逆手に取れば、意図的な自爆スイッチになる。外部非公開の閉域管理画面や、想定した証明書チェーン以外とは金輪際通信させたくないキオスク端末専用アプリのような用途に限定すれば、脆弱性ではなく仕様として機能する。攻撃者が別のCAから正規に証明書を騙し取っても、ピン留めした鍵と一致しない限りそのブラウザは二度と接続できない。中間者攻撃はおろか、正規CAの誤発行にすら効く、更新運用さえ厳格にできるなら最強クラスの証明書検証になる。

**技術の魅力**: 世の中のほとんどの「非推奨」は機能不足や陳腐化が理由だが、HPKPは"効きすぎる"が故に葬られた珍しい仕様。防御が強すぎて自分自身への攻撃手段になるという逆説そのものが、閉じた環境なら弱点ではなく特徴になる。ブラウザベンダーが「一般ユーザーには危険すぎる」と判断した機能を、母数を自分で管理できる限定環境だけに絞って復権させる発想が効いている。

**本来どこで使われてるか**: 標準ブラウザからは撤去済みで、後継のCertificate Transparencyがより安全な代替として全ブラウザで既定動作している。一方でHPKPと同じ「事前共有鍵/証明書ピン留め」の発想自体は、モバイルアプリのSSL Pinning（OWASP MASVSが推奨）や、IoTデバイスが特定バックエンドとだけ話す用途では今も現役で使われ続けている。
出典: https://en.wikipedia.org/wiki/HTTP_Public_Key_Pinning / https://scotthelme.co.uk/hpkp-is-no-more/ / https://groups.google.com/a/chromium.org/g/blink-dev/c/he9tr7p3rZ8

### <a id="card-3"></a>💡 ハエの複眼が45年前に発見した"引き算だけの動き検出"が、いまカメラの中でフレームを捨てさせている——Reichardt検出器という神経回路の密輸 〔move: 異分野の手法移植 / 領域: AI/メディア処理〕

**事実**: ハエなど昆虫の視覚系は、隣接する2つの受光細胞の信号のうち片方だけをわずかに時間遅延させてから掛け算し、逆方向の組でも同様に掛け算して差し引く、という極めて単純な回路だけで「どちらへ動いたか」を検出している。1950年代にHassenstein & Reichardtが提唱し、以後カルシウムイメージングなどでハエの脳内で実際にこの通りの応答が起きていることが確認された「相関型運動検出器（Reichardt detector）」で、フレームもオプティカルフローの連立方程式も必要としない。

**何ができる**: この回路をそのままアナログ回路へ焼き込んだのが、Carver Mead研究室が切り拓いた「シリコン網膜」であり、その系譜にある現代のイベントカメラ（DVS, Dynamic Vision Sensor）は、画素ごとに明るさの変化があった瞬間だけ非同期にイベントを発火させる。フレームバッファも、画像全体を毎秒何十回も転送する帯域も要らず、静止した背景は文字通り"何も送らない"ので、動きだけを桁違いの低消費電力・低遅延（マイクロ秒オーダー）で拾える。高速でシーンが変わるロボットのビジョンや、電池で何年も動かしたいエッジセンサーに向く。

**技術の魅力**: 通常の動画AIは「フレームをまるごと撮ってから計算で動きを求める」が、この系譜は「動きが起きた画素の情報しかそもそも生成しない」。センシングと計算を分離せず、昆虫の神経回路の配線そのものをハードウェアの回路トポロジーとして直接コピーしている点が異様。ソフトウェアのアルゴリズムを移植したのではなく、生物の"配線図"をシリコンの配線図として輸入したというのが核。

**本来どこで使われてるか**: ロボット工学・自動運転のプリプロセッサとして、iniVation・Prophesee・Samsungなどがイベントカメラを商用化し、高速衝突回避や超高フレームレート相当の追跡に採用例がある。学術的にもハエの一次視覚系の応答モデルとして、Reichardt検出器は今も動物の運動視の標準モデルであり続けている。
出典: https://www.pnas.org/doi/10.1073/pnas.0407368101 / https://arxiv.org/pdf/2504.08588 / https://en.wikipedia.org/wiki/Event_camera
