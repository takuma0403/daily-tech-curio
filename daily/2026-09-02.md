### <a id="card-1"></a>🆕 時計を刻むだけの水晶が、鼻になる——マイコンのクリスタルを化学センサーに変える 〔move: センサーの転用 / 領域: 無線/組み込み/ハードウェア〕

**事実**: どんなマイコン基板にも、クロックを刻むためだけの水晶発振子が載っている。この水晶は、表面にわずかでも質量が付着すると共振周波数がわずかに下がるという性質を持つ——これがQCM（Quartz Crystal Microbalance）の原理で、市販の測定器なら0.1ナノグラム単位の質量変化まで検出できる。普段は「正確に時を刻む部品」としてしか扱われないが、その正確さの裏側は「ごく微量の付着物にも敏感に反応する」ことと表裏一体になっている。

**何ができる**: 数十円の水晶に薄いワックスやポリマーの膜を一枚コーティングし、その発振周波数をマイコン自身のタイマー/カウンタでそのまま読むだけで、専用のガスセンサーICを一切追加せずに揮発性有機化合物・湿度・食品の腐敗ガスなどを検出できる。基板にすでに載っている「時計用部品」を、配線もBOMも増やさずに化学センサーへ二重利用する発想。

**技術の魅力**: 誰も「入力デバイス」として予算計上しない部品が、実は最高クラスの感度を持つセンサーだったという非対称性が効いている。正確に時を刻むために必要な"鋭い共振"こそが、微量の質量変化を鋭敏に拾う条件そのものであり、両者は同じ物理現象の表と裏でしかない。追加コストゼロで手に入る化学感覚、というのが尖っている。

**本来どこで使われてるか**: QCMは半導体・光学薄膜の製造現場で、スパッタリングや蒸着中の成膜レートをリアルタイム監視する標準計測器として使われている。またDNAやタンパク質を検出するバイオセンサーの土台としても実用化されており、50MHz発振回路によるQCM型DNAバイオセンサーの報告例もある。ナノ多孔質酸化グラフェンをコーティングしたQCMで、魚の腐敗を示すトリメチルアミンガスを検出する研究も存在する。
出典: https://www.nanoscience.com/techniques/quartz-crystal-microbalance/ / https://www.ncbi.nlm.nih.gov/pmc/articles/PMC3231718/ / https://www.ncbi.nlm.nih.gov/pmc/articles/PMC9785972/

### <a id="card-2"></a>🔍 耳の裏の微弱電流だけで、人を"リモコン操作"する——前庭電気刺激という体のジョイスティック化 〔move: 人間/身体をプロトコルの一部にする / 領域: ワイルドカード(神経科学×VR・HCI)〕

**事実**: 耳の後ろの骨（乳様突起）に電極を貼り、そこへごく微弱な電流を流すと、内耳にある平衡感覚器官（前庭器官）が「自分は傾いている・動いている」という錯覚信号を脳へ送ってしまう。これがGVS（Galvanic Vestibular Stimulation）。本人はその信号の出所に気づかず、無意識に体勢やその後の歩行方向を"修正"しようとする。1999年のFitzpatrickらの研究では、歩行中にGVSを与えると被験者が意図した進路から実際に逸れることが確認されている。

**何ができる**: 歩行者の歩みに合わせて電流の強さを連続的に変調し続けると、本人に気づかれないまま歩く方向をじわじわ誘導できる。名古屋大学の研究では、目隠しをした被験者をGVSだけで"遠隔操縦"し、曲がりくねった経路を歩かせたり障害物や人を避けさせたりすることに成功している。画面もイヤホン音声も振動指示も要らず、耳の裏の2枚の電極とその電流波形だけが、丸ごと"操縦プロトコル"になる。

**技術の魅力**: 身体を使ったインターフェースの多くは、身体を「センサー」や「データ経路」に変える（皮膚をアンテナに、心拍を鍵に、など）が、GVSは逆に身体を「アクチュエータ」に変える。しかも命令の実体はモーターでも振動でもなく、生理的な錯覚そのもの。本人はその命令を"自分の意思による姿勢修正"として体感してしまうため、指示されているという自覚すら持てない。

**本来どこで使われてるか**: GVSはもともと前庭機能の研究や、平衡障害のリハビリテーションに使われてきた臨床・研究ツール。近年はVRの「リダイレクテッドウォーキング」研究にも応用され、狭い実空間の中で被験者を円を描くように歩かせながら、本人には「まっすぐ歩いている」と感じさせる目的で、電気・振動・冷却の各刺激方式を比較するCHI 2023の研究などが発表されている。
出典: https://icat.vrsj.org/ICAT2011_Proceedings/pdf/094-Watanabe.pdf / https://pubmed.ncbi.nlm.nih.gov/10358131/ / https://dl.acm.org/doi/10.1145/3544548.3580862

### <a id="card-3"></a>💡 まだ来ていない未来のクリックを描く——PointerEventの"予知能力" getPredictedEvents 〔move: 異分野の手法移植 / 領域: フロントエンド/グラフィックス〕

**事実**: Pointer Events仕様には`PointerEvent.getPredictedEvents()`というメソッドがあり、まだブラウザに到達していない"次のポインタ位置"を、過去の座標・速度・軌跡から予測して返す。目的は、スタイラスやタッチで絵を描くときに体感するレイテンシを消すこと。本物のイベントの到着を待たず、先に予測位置へ線を描き進めてしまう。

**何ができる**: この発想自体は、レーダーが途切れた瞬間の航空機の現在位置を直前の速度・進路から外挿し続ける航法の推測航法（dead reckoning）や、ハードディスクのヘッド位置サーボ制御が用いてきた「未来の状態を先読みして今の動作を決める」という制御理論の考え方を、ブラウザのイベントループへそのまま輸入したものにあたる。フロントエンド開発者はこの背景を意識せずとも、`getPredictedEvents()`を1行呼ぶだけで、その恩恵（Chromeの公開情報では95%のケースで予測が良好とされる）をそのまま描画アプリへ取り込める。

**技術の魅力**: 「未来を予測する」というと普通はサーバー側の統計・MLの仕事だと思われがちだが、これはブラウザのメインスレッドで1フレーム先の座標をタダで返してくるAPIとして、OSやレンダラの奥深く（Chromiumの入力パイプラインなど）に静かに埋め込まれている。しかも"外れても誰も気づかない"予測だからこそ成立する設計で、実際のイベントが来た瞬間にこっそり軌道修正して帳尻を合わせる。

**本来どこで使われてるか**: W3C/WICGのPointer Events仕様が定義する標準APIで、ChromeOS向けの`low-latency-stylus`ライブラリのように、直接レンダリング（OSコンポジタを介さずペンの線をハードウェアへ直結する仕組み）と組み合わせてスタイラス描画アプリの体感レイテンシを削るために本番採用されている。Android開発者向け公式ブログでも、この予測とダイレクトレンダリングの組み合わせがスタイラス低遅延化の柱として解説されている。
