### <a id="card-1"></a>🆕 誰も使うなと言われた1ビットが、いまも全TCPスタックの中で息をしている——URGフラグという最後の割り込み 〔move: レガシー/廃止予定機能の蘇生 / 領域: ネットワーク/プロトコル〕

**事実**: TCPヘッダには最初期からURGフラグと緊急ポインタというフィールドが存在し、「通常のデータより先に処理してほしい1バイト」を指定できる。ところが元の仕様書(RFC 793)の記述があいまいで、「緊急ポインタが指す位置」が最後の緊急バイトの直前か直後かでBSD系実装とそれ以外の解釈が割れ、以来30年以上「実装依存」のまま放置された。2011年のRFC 6093は「緊急データをそもそも帯域外(out-of-band)として扱う発想自体が誤りで、TCPは本来インラインでしか運べない」と釘を刺しつつ、直さずに現行の食い違った実装をそのまま追認するという異例の決着をつけた。

**何ができる**: クライアントとサーバー双方の実装を自分で握れる閉じた環境(社内のマイコン間リンク、組み込み機器のペア同士)なら、この「1バイトだけ横入りする」性質をわざと使い、通常のペイロード用ソケットとは別に多重化フレーミングを一切実装せずに「いま送っている大きなデータを今すぐ中断しろ」という緊急停止シグナルを割り込ませられる。HTTP/2のストリーム優先度やQUICのような重いアプリ層多重化を持ち込まずに、生のTCP1本の中だけで"割り込み専用チャンネル"が作れる。

**技術の魅力**: 順序保証・信頼配送というTCPの根幹(バイト列は必ず送った順に届く)の中に、唯一「順序を無視して先に見てもいい」という例外だけを残しているのが面白い。しかもIETF自身が「その例外の意味は仕様として矛盾していた」と認めながら、生きている実装を壊さないために矛盾ごと標準化するという、規格が現実に負けた珍しい事例でもある。

**本来どこで使われてるか**: Telnetの「Synch」機構(IAC + URG)は、リモート側のプロセスが暴走して出力を垂れ流し続けているとき、バッファに溜まった大量データを飛び越えて割り込みコマンドを届けるために使われていた。FTPの ABOR コマンドも同様にURGで送られ、詰まった転送をアプリ側のキューを待たずに止める。一方この仕組みは1997年のWinNuke攻撃でも悪用され、不正なURGセグメントを送りつけるだけでWindows 95機をブルースクリーンに落とせたため、現在は多くのファイアウォール(Check Point, Sophosなど)がURGフラグと緊急ポインタを検知すると黙って値を取り除く設定をデフォルトにしている。
出典: https://www.rfc-editor.org/rfc/rfc6093 / https://support.checkpoint.com/results/sk/sk36869

### <a id="card-2"></a>🔍 電波の往復時間だけが、嘘をつけない物差しになる——Wi-Fi測距が中継攻撃を殺す 〔move: 仕様の目的外利用 / 領域: 無線/組み込み/ハードウェア〕

**事実**: 2016年に規格化されたIEEE 802.11mc(Wi-Fi FTM, Fine Timing Measurement)は、Wi-Fiのアクセスポイントとクライアントの間で電波の往復時間をナノ秒単位でやり取りし、光速で割ることでcm〜m級の距離を測る機能。もともと屋内測位のためのおまけ機能で、GPSが届かない建物の中でも「このAPから何メートル」がわかる。ただし初期のFTMは往復時間のやり取り自体が暗号化も認証もされておらず、第三者が偽の応答を割り込ませるだけで測定距離を数十メートル単位で操作できることが2021年の研究「Here, There, and Everywhere」で示された。

**何ができる**: この"物差しとしての精度と、そのままでは誰でも偽装できる脆さ"のセットを逆手に取ると面白い。2023年のIEEE 802.11az(FTMの後継)は保護管理フレームと暗号化されたプリアンブル(secure HE-LTF)で測定そのものを認証するため、電波を中継するだけの攻撃機材では往復時間を短く見せかけられなくなる。これを使えば専用のUWBチップを積まなくても、たった1個のWi-Fi対応マイコンだけで「鍵は本当にドアの前にあるか」を物理的に証明する近接ロックが作れる。BLEの信号強度だけで近さを判定する既存の非接触ロックは電波を延長する中継器一つで簡単に騙されるが、往復時間を物理層で暗号署名するこの方式なら電波を光速より速く運べない限り距離を偽れない。

**技術の魅力**: セキュリティの世界で「近さ」を証明するのは実は難しい問題(distance bounding)で、多くの近接認証は結局「信号の強さ」という簡単に偽装できる代理変数に頼ってきた。FTM/802.11azは、往復時間という物理法則(光速)そのものを証拠に組み込むことで、"アプリ層でどれだけ工夫しても崩せない下限"を作っている。屋内地図アプリのための機能が、そのまま暗号学的な距離証明の材料になるという転用の飛躍が効いている。

**本来どこで使われてるか**: AndroidはAPI 28からWi-Fi RTT APIとしてFTMを標準搭載し、Googleの屋内マップや店舗内ナビ、資産追跡システムの位置測位に使われている。802.11azはさらに、自動車の非接触キーやスマートロックのリレーアタック対策として業界標準化が進められている。
出典: https://arxiv.org/pdf/2509.03901 / https://dl.acm.org/doi/10.1145/3448300.3467828 / https://www.helpnetsecurity.com/2023/08/25/jonathan-segev-ieee-802-11az-standard/

### <a id="card-3"></a>💡 死体に群がる虫の"入れ替わる順番"が、侵入者の滞在期間を暴く手口に変わる 〔move: 異分野の手法移植 / 領域: ワイルドカード(法医昆虫学×デジタルフォレンジック)〕

**事実**: 法医昆虫学には死亡推定時刻を出す2つの手法がある。ひとつは死体に最初に産みつけられた卵の発育段階と気温から積算温度(degree-day)で経過時間を逆算する「発育モデル」、もうひとつは死体が腐敗の各段階を経るにつれてハエ→甲虫→…と全く異なる昆虫種の"群れ"が入れ替わりながら定着していく「遷移(succession)モデル」。発育モデルは最初の成虫が羽化してしまうと使えなくなるが、遷移モデルはその後も数週間から数ヶ月単位で機能し続ける、という実務上の使い分けがある。

**何ができる**: この"種の入れ替わる順序そのものが時間の物差しになる"という発想を、そのままデジタルフォレンジックの侵害タイムライン推定に輸入できる。侵害されたシステムでは攻撃者のタイムスタンプ改竄(timestomping)によってファイルの生成・更新時刻はいくらでも偽装できるが、実際に投入されるツールの"種類"は攻撃キャンペーンの進行段階を素直に反映する——初期潜入直後は偵察・列挙系ツールが、数日後には永続化の仕込みが、さらに後には横展開・認証情報奪取ツールが、という具合に。個々の時刻を1つも信用せず、「どの種類のツールがまだ現れていないか/すでに現れているか」という"生態系の構成"を、既知の侵害事例群で校正した遷移モデルに当てはめるだけで、侵害開始からの経過段階を推定できる。

**技術の魅力**: 攻撃者は個々のログの時刻は偽装する動機も手段も持っているが、「侵害の何日目にどの種類のツールを持ち込むか」という行動の順序そのものまで気にして偽装することは稀。法医昆虫学が「死体そのものの時計」ではなく「死体に群がる生態系の遷移」を証拠にするのと同じ発想の転換——個別の証拠ではなく、証拠の集合が形作る"順番"を証拠にするところが効いている。

**本来どこで使われてるか**: 法医昆虫学は実際の刑事事件で腐敗の進んだ遺体の死亡推定時刻を出す標準的な鑑定手法として、各国の検死・法医学機関で運用されている。発育段階の観察には現場の気温データとの照合が必須で、遷移モデルの運用には地域・季節ごとに固有の昆虫相データベースを事前に整備しておく必要があるとされる。
出典: https://www.ncbi.nlm.nih.gov/books/NBK549867/ / https://pmc.ncbi.nlm.nih.gov/articles/PMC8066566/
