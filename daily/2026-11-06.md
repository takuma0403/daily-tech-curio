### <a id="card-1"></a>🆕 DNSのゾーン転送を、自作の差分同期プロトコルとして借りる——IXFRと「2³¹で折り返す」シリアル番号 〔move: 仕様の目的外利用 / 領域: データ/同期/ストレージ〕

**事実**: DNSのセカンダリサーバーは、プライマリから「ゾーン」というレコードの束を複製して持つ。その仕組みが AXFR（全量転送）と IXFR（RFC 1995、1996年。差分転送）。IXFR では、クライアントが「自分が持っているSOAシリアル番号は N です」と送るだけで、サーバーは N から現在までの追加・削除の差分だけを返す。差分を送れない場合は全量転送に自動で切り替わる。地味なのは、シリアル番号が普通の整数ではない点で、RFC 1982 の「シリアル番号算術」により32ビットで折り返しながら大小を比べる（差が 2³¹ 未満なら進んだ方が新しい）。

**何ができる**: 「バージョン番号を送ると差分だけ返る」という同期プロトコルが、DNSサーバー（BIND、Knot、NSDなど）に完成品として入っている。そこで、同期したいデータ（設備リスト、許可MACアドレス表、設定のキー/値）をゾーンのTXTレコードとして書き、拠点側は `dig @primary example.lan IXFR=<手元のserial>` を叩くだけで差分を受け取れる。自前のREST APIも、同期用のDBも書かない。さらに NOTIFY（RFC 1996）が付いてくるので、更新時にプライマリから全拠点へ「変わったよ」というプッシュまで揃う。5分デモ: `nsd` か `knotd` を1つ立て、ゾーンに1行足してserialを+1し、別端末で `dig IXFR` の応答に差分行だけが乗るのを見る。

**技術の魅力**: 「DNSは名前引きの道具」という前提を外すと、世界で最も枯れた2地点間のレプリケーション機構として見えてくる。しかも不揃いな世界を想定して作られていて、差分を持っていなければ全量に落ち、折り返す番号で何十年更新し続けても動き続ける。ベクタークロックもCRDTも出てくる前の1996年に、「単調増加の版番号＋変更履歴」というログ型同期の最小形が標準化されていた点が効いている。

**本来どこで使われてるか**: 権威DNSのプライマリ/セカンダリ間のゾーン複製。ルートゾーンや大手TLDの運用でも、複数の事業者のサーバーに複製を配る基礎として使われている。シリアル番号の比較規則は RFC 1982 に独立して定義され、SOAのシリアルのために作られた。IXFR は差分を送れないとき全量転送にフォールバックする、とRFC 1995自身が定めている。
出典: https://www.rfc-editor.org/rfc/rfc1995 / https://www.rfc-editor.org/rfc/rfc1982

### <a id="card-2"></a>🔍 LEDは光るだけの部品ではない——逆向きにつなぐと、光を「数える」光センサーになる 〔move: センサーの転用 / 領域: 無線/組み込み/ハードウェア〕

**事実**: LEDは発光ダイオードだが、半導体の接合である以上、光が当たれば電流が生じる光ダイオードとしての性質も持っている。マイコンのピン2本で、LEDのカソードをHIGH、アノードをLOWにして逆向きに電圧をかけ、接合容量を充電する。その後、カソード側のピンを入力に切り替えて浮かせると、当たった光に比例した漏れ電流で容量が放電されていく。ピンが「HIGH」と読む状態からLOWに落ちるまでの時間を測れば、それが光量になる。明るいほど放電は速い。ADCは要らない。

**何ができる**: 光るLEDが光を測るので、1個のLEDで「表示と受光」を時分割にできる。たとえば、LEDを点灯して見せる→数ミリ秒だけ逆向きにつないで周囲光を測る→明るさに合わせて自分の輝度を自動調整する。センサー部品ゼロの自動調光表示になる。さらに、同色のLED同士なら一方が発した光をもう一方が受けるので、2個のLEDを向かい合わせにして「光の通信」や「間を通ったものの検知」もできる。5分デモはArduinoにLED1個で、暗い部屋で手をかざして放電時間が伸びるのを見る。

**技術の魅力**: 部品の「向き」を変えるだけで役割が反転する。LEDは自分の出す色と近い波長にもっとも敏感なので、赤LEDは赤い光に、緑LEDは緑の光に強く反応する。つまり1個のLEDが「色つきの光センサー」にもなる。製造ばらつきで感度は揃わないが、「光らせるための素子がそのまま測る素子でもある」という対称性がきれいだ。

**本来どこで使われてるか**: 一般にLEDは表示専用だが、この「LEDを受光器に使う」技法は電子工作の古典で、SparkFunのチュートリアルや Make: などの電子工作メディアで繰り返し紹介されてきた。学術的にも、白色LEDを逆バイアスの光センサーにする特性評価の研究がある（Arduino UNOの10ビットADCと10MΩのプルアップで評価）。逆向きのLEDは非常に高インピーダンスなため電気ノイズを拾いやすい、という注意も共通している。

### <a id="card-3"></a>💡 菌は「人数」を数えてから光る——クオラムセンシングを、デバイスの台数しきい値に移植する 〔move: 異分野の手法移植 / 領域: ワイルドカード(微生物学×分散システム)〕

**事実**: 発光バクテリアの Vibrio fischeri（ハワイ産イカの発光器に棲む）は、単独で漂っているときは光らない。細胞がオートインデューサー（AHL、3-oxo-C6-HSL）という小さな分子を絶えず少量ずつ出していて、周囲の細胞が増えるとその濃度が上がる。濃度が閾値（文献では100〜200nM程度とされる）を超えたときだけ、LuxR という受容体を介して発光酵素ルシフェラーゼの遺伝子が一斉にONになる。これが「クオラムセンシング」で、1970年に「autoinduction」と名づけられた。

**何ができる**: これを分散システムに写すと「リーダー選出も人数カウントも要らない、人数しきい値スイッチ」ができる。各デバイスは自分の存在を示す弱いビーコン（BLEアドバタイズなど）を周期的に出し、周囲のビーコン数を指数的に減衰させながら足し込んだ「濃度」を持つ。濃度がしきい値を超えたら、全員が自律的にモードを切り替える（たとえば部屋に5台以上集まったら省電力のメッシュ運用に入る）。台数が減れば、減衰で濃度が下がって自然に元に戻る。さらに、出す量を濃度で増やす（正のフィードバック）ことで、しきい値付近でバタつかない急峻なスイッチになる。

**技術の魅力**: 中央の誰も「全員で何台いるか」を知らないのに、全員がほぼ同時に同じ判断へ移る点が効いている。ハンドシェイクもIDの表も持たず、必要なのは「濃度」というただ1つの足し算の状態だけ。しかも古い情報は減衰で勝手に消えるので、離脱したノードの掃除（タイムアウト管理）が仕組みに溶け込んでいる。生物がやっている「数えるより混ぜる」解を、そのまま状態機械に落とせる。

**本来どこで使われてるか**: 本物の細菌では、V. fischeri がイカの発光器の中で高密度になったときだけ発光し、生物発光の古典的なモデルになっている。同じ仕組みは病原菌の毒素産生やバイオフィルム形成の制御にも見つかっていて、AHL を分解して感染を抑える研究（クオラムクエンチング）もある。
