### <a id="card-1"></a>🆕 認証サーバーに聞かず、持ち主が自分で権限を削って他人に渡せる——Macaroons 〔move: 制約の極端化 / 領域: セキュリティ/認証〕

**事実**: Macaroons は Google らが2014年に発表した認可トークンの方式で、中身は「HMACの鎖」でしかない。発行者は秘密鍵でトークンの識別子にHMACをかけて署名を作る。その後、持ち主は「caveat（条件）」として `expires < 12:00` や `path = /photos/` のような文字列を追加でき、そのたびに直前の署名を鍵にして新しいHMACを作り直す。署名は一方向なので、条件を足すことはできても、遡って外すことはできない。見落とされがちなのは、この「足す」操作に発行者の鍵が要らないこと。

**何ができる**: 持ち主がサーバーに一切問い合わせず、手元で「読み取り専用・今日中・このフォルダだけ」に権限を絞った子トークンを作って、他人や別のデバイスにそのまま渡せる。検証側は秘密鍵から鎖を再計算して、全caveatが満たされているかを見るだけ。第三者の確認が要る条件（「このユーザーがログイン済みであること」）も、証明を別途添えることで外部サービスに委ねられる。

**技術の魅力**: 委任のたびに発行サーバーへ往復する、という認可の常識を、ハッシュ関数の一方向性だけで逆転している。権限は足し算ではなく引き算でしか動かない、という性質が暗号の側から保証される。JWTのように「中身を読めば全部わかる」代わりに、署名の鎖が改ざんも権限拡大も拒む。

**本来どこで使われてるか**: Google の論文が出発点で、クラウド内のサービス間認可を想定して設計された。実装は libmacaroons や pymacaroons などがあり、Lightning Network の LND は API 認証（admin.macaroon / readonly.macaroon など）にmacaroonを採用している。
出典: https://research.google/pubs/macaroons-cookies-with-contextual-caveats-for-decentralized-authorization-in-the-cloud/ / https://www.ndss-symposium.org/wp-content/uploads/2017/09/04_3_1.pdf

### <a id="card-2"></a>🔍 LEDの点滅を、スマホの「撮影の遅さ」で読む——ローリングシャッターを受信機にする 〔move: センサーの転用 / 領域: 無線/組み込み/ハードウェア(光)〕

**事実**: スマホのCMOSカメラは、画面全体を一瞬で撮るのではなく、1行ずつ時間をずらして読み出す（ローリングシャッター）。普通は動体のゆがみとして嫌われる欠陥だが、数kHzで点滅するLEDを撮ると、行ごとに明るさが違うため、1枚の写真に縞模様としてそのまま焼き付く。フレームレートは30fps程度でも、縞の1本1本が数十μs〜数百μsの時間分解能を持つ。

**何ができる**: 秒30コマのカメラで、その何百倍も速い点滅を読める。LEDを高速でON/OFFして縞の太さや有無にビットを載せれば、改造なしのスマホ1台が光通信の受信機になる。実験では約10kHzで点滅させたLEDから、1枚の画像に約28ビットを詰めて読む報告がある。肉眼にはちらつきが見えない速さなので、照明として使いながらIDやメッセージを送れる。

**技術の魅力**: 欠陥をそのまま「高速サンプリング」に読み替えているところ。センサーを作り替えず、読み出し順序という副作用だけで、見かけのフレームレートを桁違いに引き上げている。送信側はマイコンのGPIO1本とLEDで済む。

**本来どこで使われてるか**: 光カメラ通信（Optical Camera Communication, OCC）として研究され、IEEE 802.15.7 の可視光通信規格にカメラ向けのモード（C-OOK）が含まれる。Intel は2016年にIEEEへ、改造不要のスマホカメラを受信機とする提案を出している。店舗内の位置案内など、照明にIDを乗せる用途が想定されている。ただし規格に載っているのはカメラ向けPHYの一部で、ローリングシャッター方式の細部の多くは研究・提案段階。
出典: https://mentor.ieee.org/802.15/dcn/21/15-21-0228-01-007a-hybrid-rolling-shutter-signal-for-optical-camera-communication.pdf / https://mentor.ieee.org/802.15/dcn/16/15-16-0006-01-007a-intel-occ-proposal.pdf / https://pmc.ncbi.nlm.nih.gov/articles/PMC7348962

### <a id="card-3"></a>💡 コオロギの鳴く速さは温度計の目盛りだった——ドルベアの法則を音で読む 〔move: 異分野の手法移植 / 領域: ワイルドカード(生物×計測)〕

**事実**: 1897年に物理学者のアモス・ドルベアが発表した経験則で、カンタンの仲間（snowy tree cricket）が鳴く回数は気温に比例する。有名な形は「15秒間の鳴き声の数 + 40 = 華氏温度」。1分あたりなら 50 + (回数 − 40)/4 とも書ける。変温動物の筋肉の動きが温度に支配される、という生理がそのまま周波数に出ている。

**何ができる**: 電池も温度センサーもない庭の茂みに、無給電の温度計がいる。録音を取って鳴き声の周期だけ数えれば、気温が1度前後の精度で推定できる。マイコンにマイクを付けて、夜間の外気温を「聞いて」ログに残すこともできる。種ごとの別式もあり、較正すれば精度が上がる。

**技術の魅力**: 温度センサーの値を読む代わりに、生き物の発振器を計測器として借りている。しかも式が線形で、手で数えられるほど単純。ただし外れる条件も明確で、一定の温度域（おおむね50〜100°F）でしか成り立たず、フィールドコオロギなど種を取り違えると狂う。「どこまで信用できるか」を自分で見積もる感覚を磨く題材にもなる。

**本来どこで使われてるか**: 学校の理科教材や市民科学の定番ネタとして広く使われ、NOAAも解説記事を出している。式は種ごとに変わり、建物の近さや地域でも当てはまりが変わる、とNOAAは注意している。実際に正式な気象観測に使われるわけではなく、観察の入口としての知見。
出典: https://en.wikipedia.org/wiki/Dolbear%27s_law / https://www.noaa.gov/office-of-education/explainers/can-crickets-tell-temperature-answer-is-in-their-chirp
