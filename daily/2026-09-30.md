### <a id="card-1"></a>🆕 「宛先を2バイトに縮めるだけで、他人の無線マウスの電波が聞こえてしまう」——nRF24L01+の擬似プロミスキャス受信 〔move: 仕様の目的外利用 / 領域: 無線/組み込み/ハードウェア〕

**事実**: 安価な2.4GHz無線チップnRF24L01+は、受信側のアドレス(3〜5バイト)がそのまま同期ワードを兼ねる設計で、「アドレスが合った電波しか拾わない」ので公式には盗聴(プロミスキャス受信)ができない。ところが2011年にTravis Goodspeedは、アドレス長を2バイトに縮め、CRCを切り、アドレスをプリアンブルと同じ0xAA(または0x55)にする、という設定の組み合わせを示した。すると宛先を問わず「プリアンブルの直後に来るもの」が雑音混じりで大量に流れ込み、その中から有効なアドレスを後で選別できる。データシートに書かれた機能の外にある、レジスタ設定だけの抜け道なので見落とされやすい。

**何ができる**: 数百円のモジュール1枚とマイコン1個で、自宅周辺の「独自2.4GHz無線の住民台帳」が作れる。Wi-Fi/BluetoothのスキャナーにはSSIDもMACも映らない無線マウス・キーボード・ドアチャイム・ラジコンのアドレスを列挙し、見つけたアドレスに張り付いて実際のパケット(キー入力の暗号化有無まで)を眺められる。まず自分の家に潜む脆弱な無線機器を洗い出す「自宅の電波の棚卸し機」になる。

**技術の魅力**: 「盗聴を防ぐ設計」が、チップの設定項目を規格外の値にするだけで崩れるという非対称性が面白い。守りの実体が「アドレスを知らないと同期が取れない」という程度の暗黙の秘匿で、雑音を大量に集めて統計的に本物を拾い出せば足りてしまう。ハードの機能を1ビットも改造せず、レジスタ書き込みの順番だけで攻守が入れ替わる。

**本来どこで使われてるか**: nRF24L01+は安価な無線マウス・キーボードのドングル、玩具、ホビー用センサー網などに広く載っている。Goodspeedの手法は、Bastilleのマーク・ニューリンが2016年に公開した「MouseJack」(無線マウス/キーボードのドングルに任意のキー入力を注入できる脆弱性群)の研究の土台になった。
出典: http://travisgoodspeed.blogspot.com/2011/02/promiscuity-is-nrf24l01s-duty.html / https://sra.io/wp-content/uploads/2018/02/MouseJack-whitepaper-v1.1.pdf

### <a id="card-2"></a>🔍 Wi-Fiも電波時計も要らない、FMラジオが毎分そっと時刻を配っている——RDSのクロックタイム(CT)グループ 〔move: レガシー/廃止予定機能の蘇生 / 領域: ワイルドカード(放送)〕

**事実**: FM放送には、音声の裏で57kHzの副搬送波に1187.5bpsのデータを載せるRDS(Radio Data System)が同居している。57kHzはステレオのパイロット信号(19kHz)の3倍で、ステレオ成分と干渉しない位置に選ばれた。データは26ビットのブロック4つ=104ビットのグループで送られ、局名・曲名(RadioText)・交通情報などに並んで、日時と現地時間オフセットを運ぶクロックタイム(CT)グループがある。車のラジオの時計が勝手に合うのはこのためだが、スマホ全盛の今、単体で活かそうとする人はほとんどいない。

**何ができる**: RDS対応のFM受信チップ(Si4703など)をマイコンに1個つなぐだけで、Wi-Fi・NTP・GPS・携帯回線なしに、UTCと現地時刻のオフセットが空から降ってくる。電池で数年動く屋内ロガーや、電波の届かない地下・山小屋の時計合わせの「時刻源」になる。受信専用なので、こちらの電波は一切出ない。

**技術の魅力**: 「音楽を聴くための電波」に、誰にも頼まれず時刻が乗っているのが美しい。しかも電波時計(WWVBやJJY)が届かない地域でも、FM局さえ入ればほぼ世界中で同じことができる。精度は伝送のばらつきでUTCの±100ms程度と割り切られていて、「ロガーの時計合わせには十分、秒単位で厳密な用途には不足」という現実的な線引きも面白い。

**本来どこで使われてるか**: カーラジオや一部のデジタル時計・ラジオの時計自動補正。RDS自体は欧州で普及し、局名の表示やAF(別周波数への自動切替)、交通情報の割り込み(TP/TA)に使われている。ただし局によってCTを送っていない・不正確なことがあるので、複数局で照合する運用が現実的。
出典: https://www.rds.org.uk/2010/pdf/RDS_ebook_9782940536207.pdf / https://en.wikipedia.org/wiki/Radio_Data_System

### <a id="card-3"></a>💡 数えるのをやめたら、順番も重複も気にしなくてよくなった——HyperLogLogの「max合流」という無料のCRDT 〔move: 制約の極端化 / 領域: データ/同期〕

**事実**: HyperLogLogは、要素をハッシュして先頭に並ぶ0の個数の最大値だけをレジスタに覚え、ユニーク数を推定する確率的データ構造。Redisでは16,384個のレジスタ(1個6ビット)で約12KBだが、本質は「レジスタごとのmax」という単純な操作だけ。2つのHLLを合わせる(PFMERGE)ときも、各レジスタのmaxを取るだけで、結果は元の全要素の和集合を数えたのと同じ推定になる。max演算は交換・結合・冪等なので、どんな順番で、何度合流させても同じ状態に収束する。

**何ができる**: 数百バイトのHLLを載せたマイコンを街に散らし、すれ違うたびに(BLEなどで)互いのレジスタをmaxで合流させれば、中央サーバーなしで「今日この街を通ったユニークな端末数」が全員の手元に収束する。同じ人を2つのセンサーが数えても、同じ情報を何度ゴシップしても、二重カウントにならない。256レジスタ(約200バイト)なら誤差は約1.04/√256≒6.5%で、ESP32以下のマイコンにも余裕で載る。

**技術の魅力**: 「重複排除つきのカウント」という一見サーバーがいる仕事が、max合流だけで、順序保証も通信の確実性も要らない分散処理になる。CRDTの教科書的な設計を、意識せずに満たしている。しかもスケッチから元の要素を取り出せないので、生のMACアドレス台帳を持ち歩かずに済む(ただし完全な匿名性の保証ではない)。

**本来どこで使われてるか**: RedisのPFADD/PFCOUNT/PFMERGE(名前のPFはHLLを考案したPhilippe Flajoletにちなむ)。大規模サービスの日次・時間別のユニークユーザー数集計など、事前に作った時間別のスケッチをmax合流するだけで任意期間のユニーク数を出す用途に使われる。
出典: https://redis.io/docs/latest/develop/data-types/probabilistic/hyperloglogs/ / https://en.wikipedia.org/wiki/HyperLogLog

🔎 検索ワード: `HyperLogLog merge register max` / `Redis PFMERGE HyperLogLog` / `HyperLogLog CRDT gossip sensor` / 「HyperLogLog 合流 分散 ユニーク数」
