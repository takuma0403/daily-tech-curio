### <a id="card-1"></a>🆕 オートフォーカスの左右の目が、そのままステレオカメラになる——Dual Pixel 〔move: センサーの転用 / 領域: AI/メディア処理〕

**事実**: 近年のカメラセンサーの各ピクセルは、像面位相差AFのために左右2つのフォトダイオードへ分割されている(Dual Pixel CMOS)。これは本来「ピントを瞬時に合わせる」ための機構だが、実はこの2つのフォトダイオードは、レンズの左半分・右半分をそれぞれ通った光を受けており、およそ1mmの微小な基線長を持つ立派なステレオペアになっている。ほとんどのカメラアプリはこの左右情報を単純加算して1つの輝度値に潰し、捨てている。

**何ができる**: 左右のサブピクセル画像を分離して読み出せば、複眼レンズも追加のデプスセンサーも使わず、単眼カメラ1つでシーンの視差(≒奥行き)を推定できる。GoogleはこれをPixelスマホの「ポートレートモード」に応用し、専用の距離センサーなしで被写界深度合成とデフォーカスぼけの深度マップ推定を実現した。同じ原理は、単眼カメラしかない防犯カメラや内視鏡に奥行き情報を後付けする用途にも展開できる。

**技術の魅力**: 「ピントを合わせるための脇役データ」が、実は捨てるにはもったいないステレオ画像そのものだったという非対称性が効いている。新しいハードウェアを足すのではなく、センサーが毎回作っているのに誰も読み出していない情報を"発掘"するだけで新機能が生える。しかも視差はぼけ量とも絡み合い、素朴なステレオアルゴリズムでは解けない曖昧性(ambiguity)があるため、そのままでは使えず学習ベースの手法が要る、という一筋縄でいかなさも良い。

**本来どこで使われてるか**: Dual Pixel CMOS AFはCanonが2013年に実用化し、その後多くのスマホ・ミラーレス機に広まった像面位相差AFの高速化機構。Googleはこれを転用し、論文「Learning Single Camera Depth Estimation using Dual-Pixels」(ICCV 2019)およびPixel 3/4のポートレートモード実装として発表している。
出典: https://arxiv.org/abs/1904.05822 / https://research.google/blog/learning-to-predict-depth-on-the-pixel-3-phones/

### <a id="card-2"></a>🔍 野生動物の個体数調査法が、ソフトウェアのバグの"生き残り数"を数える——Capture-Recapture 〔move: 異分野の手法移植 / 領域: ワイルドカード(生態統計×ソフトウェア工学)〕

**事実**: 生態学のcapture-recapture法(標識再捕獲法)は、池の魚を一部捕まえて印をつけて放し、後日また捕獲した際の「印つき個体の再捕獲率」から池全体の総個体数を逆算する、19世紀からある古典的な統計手法。ソフトウェア工学では1990年代から、これをコードレビューに横流しする研究が続いている。複数のレビュアーが同じコードを独立にレビューし、レビュアーAとBが両方見つけたバグの重なり具合から、まだ誰も見つけていない"未捕獲のバグ"の総数を統計的に推定する。

**何ができる**: レビュー参加者2人以上の指摘の重複率さえ分かれば、全数を数え上げなくても「このモジュールにはレビュー後もあと何件バグが残っていそうか」を見積もれる。IBMのRational Team Concert(Jazz)開発チームの実際のコードレビューログにこの手法を適用し、残存欠陥数を推定した研究が報告されている。追加レビューにどれだけ工数を割くべきか、リリース可否の判断材料になる。

**技術の魅力**: 「魚を数える理論」と「バグを数える」が、数学的にはまったく同じ構造(見つかったものの重なりから、見つかっていないものの数を逆算する)だという発見が面白い。魚にもバグにも共通するのは「観測されない限り存在を確認できない」という一点で、その"見えなさ"の統計学だけを抽出し、分野をまたいで丸ごと移植している。

**本来どこで使われてるか**: もともとは野生生物の個体数調査(魚類・鳥類・昆虫の生息数推定)や疫学での感染者数推定(未診断患者数の推定)に使われる標準的な統計手法。ソフトウェア工学への応用はEick, Loh, Vanderらの1990年代の研究以降、コードインスペクションの欠陥推定モデルとして継続的に研究されている。
出典: https://link.springer.com/article/10.1023/A:1009728205264 / https://www.researchgate.net/publication/266630368_Defect_Estimation_using_Capture-Recapture_in_IBM_Jazz

### <a id="card-3"></a>💡 電源線を1本消す——1-Wireの寄生電力が配線をGNDと信号線だけにする 〔move: 制約の極端化 / 領域: 無線・組み込み・ハードウェア〕

**事実**: DallasのDS18B20温度センサーなどが使う1-Wireバスは、本来GND・信号線(DQ)・VDDの3本で動く。だが「パラサイトパワー」モードでは、信号線がHighの間だけホストがプルアップ抵抗経由でチップ内の小さなコンデンサ(CPP)を充電し、バスがLowになっている通信中はそのコンデンサに蓄えた電荷だけでチップを駆動する。つまり電源線そのものを信号線が肩代わりする。

**何ができる**: 電源用のVDD線を完全に省略でき、配線はGNDと信号線の2本だけで温度センサーを何個も1本のバスに直列に生やせる。壁の中や屋外の配管に何十個も埋め込むセンサー網で配線コストが劇的に下がる。ただし温度変換中はチップの消費電流が跳ね上がるため、バスをHighに強制固定して"外部から電力供給"してやらないとコンデンサが枯渇する——配線が減る代わりに、ホスト側のタイミング制御はシビアになるというトレードオフが乗っている。

**技術の魅力**: 「データを送る線」と「電気を送る線」は別物だという前提そのものを疑い、信号線の"High状態"を電源としても二重利用する発想が効いている。物理的には同じ1本の銅線が、瞬間ごとに役割を切り替えて配線という制約を極限まで削っている。

**本来どこで使われてるか**: Maxim Integrated(旧Dallas Semiconductor)の1-Wireデジタル温度センサー(DS18B20/DS18S20/DS1822)やiButton系デバイスの標準機能。倉庫・屋外・壁内など多点配線が面倒な環境の温度監視で使われており、専用の"PARパッケージ"(DS18B20-PAR)ではVDDピンをGNDに落とす配線すら不要になっている。
出典: https://www.analog.com/media/en/technical-documentation/data-sheets/ds18b20.pdf / https://www.analog.com/en/resources/design-notes/ds18b20pards18s20pards1822par-advantages-for-remote-temperature-sensing.html
