### <a id="card-1"></a>🆕 中身を明かさず"同じ回線"だけを証明する——TLS Exported Keying Materialという合鍵 〔move: 仕様の目的外利用 / 領域: セキュリティ/認証〕

**事実**: TLSのハンドシェイクが作る本当のマスターシークレットは外に出せない設計になっているが、RFC 5705（TLS 1.3ではRFC 8446 §7.5）は「マスターシークレットからPRFで別の鍵を追加で“輸出”する」口を用意している。これがExported Keying Material（EKM）。中身は漏らさず、しかし同じTLSセッションでなければ絶対に同じ値を再現できない、という性質だけを外部プロトコルに渡せる。

**何ができる**: EKMをそのまま持ち出すと、「このやりとりが確かに“あの”TLS接続の上で行われた」ことを、追加の鍵交換もラウンドトリップも足さずに証明できる。RFC 9266の“tls-exporter”チャネルバインディングはこれを使い、SCRAM等の認証情報がTLSを剥がされて別回線に中継・リプレイされる攻撃を機械的に潰す。QRコードでログインを他デバイスに引き渡す方式にも同じ発想が使え、“読み取った側の接続”と“表示した側の接続”のEKMを突き合わせるだけで、フィッシングサイトが割り込んだQR中継（quishing）を検知できる——新しい暗号を足さず、既にそこにあるTLSの副産物を照合材料に変えるだけで済む。

**技術の魅力**: 普通、認証を1段強くするには鍵交換をもう1往復増やす。EKMはその代わりに“今ある接続からもう1個、別の目的の鍵を絞り出す”という方向で強度を稼ぐ。マスターシークレットそのものは決して渡さず、その影だけを渡す非対称性——渡された側はそこから元の鍵を逆算できないのに、同じ接続の当事者同士なら必ず値が一致する、という一方向性が効いている。

**本来どこで使われてるか**: 企業WiFi（WPA2/3-Enterprise, 802.1X）のEAP-TLSは、認証用のTLSハンドシェイクからEKMで直接MSK/EMSKを絞り出し、それがそのままWiFiの暗号鍵の元になる——つまり“認証専用のはずのTLS接続”が“回線そのものの暗号鍵”まで兼務している。RFC 9266のtls-exporterはSASL SCRAM-PLUSやgRPCの認証などで、TLS 1.3のセッション再開/0-RTTで壊れた旧来のtls-uniqueバインディングを置き換える標準として2022年に採用された。
出典: https://www.rfc-editor.org/rfc/rfc5705.html / https://www.rfc-editor.org/rfc/rfc9266.html

### <a id="card-2"></a>🔍 受信確認という概念を丸ごと捨てたファイル配送——RaptorQという"数式の雨" 〔move: 制約の極端化 / 領域: データ/同期/ストレージ〕

**事実**: 普通のファイル転送は「届いたパケット番号」を送り主に逐一伝え、抜けを再送してもらう。RaptorQ（RFC 6330, Raptor系フォンテンコードの最新版）はこの前提を丸ごと捨てる。元データをブロックに分け、そこから理論上無限に生成できる“符号化シンボル”を送り続けるだけで、受信側はどのシンボルが何番目に届いたか・どれが抜けたかを一切気にせず、必要個数さえ集まれば（ほぼ元のブロックと同数）ブロック全体を復元できる。

**何ができる**: 送信側は受信者の数も受信状況も知らないまま、ただ符号を放流し続けられる。1台の受信機が電波状況で半分取りこぼしても、別の受信機が別の半分を取りこぼしても、それぞれ残りをただ待てば揃う——ACKもNAKも再送要求も、そもそも上り回線すら要らない。衛星や地上波放送のような“送りっぱなし”回線で巨大ファイルを大量の受信者に同時配布する用途に極端に強く、ATSC 3.0（次世代地上デジタル放送）は動画配信そのものにこれを採用している。

**技術の魅力**: 誤り訂正符号は普通「決まった量の冗長」を足して有限個の誤りまで直す設計だが、フォンテンコードは冗長の量という概念自体を無限に開放し、「どれだけ集めれば直るか」を受信側の運任せにする。制御チャネルという発想そのものを消してしまう極端さが効いていて、“信頼性”を実現する手段からフィードバックループを完全に取り除けることを示している。

**本来どこで使われてるか**: ATSC 3.0地上デジタル放送の動画・ファイル配信、DVB衛星放送でのIPマルチキャスト、QualcommのFLUTE/ROUTEプロトコル上でのブロードキャスト/マルチキャストファイル配信で標準採用されている。5Gのマルチキャストブロードキャストサービスや、IoT機器へのファームウェア一斉配布でも同じ発想が使われる。
出典: https://en.wikipedia.org/wiki/Raptor_code / https://www.rfc-editor.org/rfc/rfc6330

### <a id="card-3"></a>💡 衛星も基地局もいらないGPS——死んだ星の点滅に便乗するXNAV 〔move: 物理現象へのピギーバック / 領域: ワイルドカード(天文学・深宇宙航法)〕

**事実**: ミリ秒パルサー（高速自転する中性子星）は、自転周期が原子時計に匹敵するほど安定してX線を明滅させ続けている。しかもその周期・位置は数十年分の観測でカタログ化済みで、いわば宇宙にもとから存在する“打ち上げ不要・保守不要の灯台”である。

**何ができる**: 探査機にX線検出器を積み、複数のミリ秒パルサーのパルス到達時刻のズレを地球到達時刻の予測と比較するだけで、GPS衛星も地上局との通信も一切使わずに、自分がいま太陽系のどこにいるかを自力で割り出せる。NASAのSEXTANT実験は2017年、ISS搭載のNICER装置で4つのミリ秒パルサーを2日間観測し、オンボード計算だけで航法解を自律的に組み立てることに世界で初めて成功した。地球との通信が往復何時間もかかる木星・土星以遠の探査機にとって、これは地上局を待たずに自分の位置を知れる手段になる。

**技術の魅力**: GPSは“打ち上げて保守し続けるインフラ”に依存するが、XNAVが便乗するのは誰も作っておらず、誰にも止められない、銀河系スケールで既に存在しているインフラである。しかも精度の源は人工衛星の原子時計ではなく、中性子星という極限天体の自転そのものという非対称性が効いている——地球近傍限定のGPSと違い、原理上は太陽系のどこにいても、あるいは太陽系を出ても同じ灯台が使える。

**本来どこで使われてるか**: パルサーは元々1967年に電波観測で偶然発見された天体物理学の研究対象であり、その自転安定性は重力波検出用のパルサータイミングアレイなど基礎物理の精密測定に使われてきた。SEXTANTはそれを応用工学に転用した初の実証で、NASAは深宇宙探査機の自律航法・自律計時への実用化を将来のミッションで見込んでいる。
出典: https://www.nasa.gov/centers-and-facilities/goddard/nasa-team-first-to-demonstrate-x-ray-navigation-in-space/ / https://www.nasa.gov/directorates/stmd/station-explorer-for-x-ray-timing-and-navigation-sextant/
