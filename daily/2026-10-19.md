### <a id="card-1"></a>🆕 文字の流れ込み方で、画像の輪郭を「測る」——CSS shape-outside 〔move: 仕様の目的外利用 / 領域: フロントエンド/グラフィックス〕

**事実**: CSSの`shape-outside`は、フロート要素の周りに文章を回り込ませる形を指定する仕様で、`url()`で画像を渡すと画像のアルファ値が`shape-image-threshold`（既定0）を超えた部分が「障害物」になる。重要なのは、この輪郭計算をレイアウトエンジンが毎回やってくれて、結果は各行の開始位置・幅として文字の座標にだけ現れること。画素を直接読む`getImageData`とは別の経路で、形の情報がレイアウトに滲み出す。

**何ができる**: 透過PNG（や生成したSVG）を1枚フロートさせ、その横に1文字ずつの`<span>`を流し込んで`getBoundingClientRect()`で座標を読むと、画像の各行の「左端がどこか」が列として得られる。これはシルエットの輪郭断面そのものなので、形の判定・当たり判定・輪郭のベクタ化を、canvasもピクセル走査も書かずに行える。`shape-image-threshold`を動かせば等高線のように異なる閾値の輪郭が取れる。

**技術の魅力**: 「文章の回り込み」という装飾用の機能が、実は画像→1次元の輪郭列への変換器として使える点が面白い。アルファ閾値・マージン（`shape-margin`）・行高が揃うと、ブラウザが勝手に行ごとの走査線で形を切ってくれる。ただし`shape-outside`の画像はCORS適用が必要で、読めるのは自分が出した形だけという制約がむしろ安全弁になっている。

**本来どこで使われてるか**: 雑誌風の組版。人物の切り抜き写真の輪郭に沿って本文を回り込ませる、円形・多角形（`circle()` `polygon()`）の周りに文章を流す、といった見せ方に使われる。仕様はCSS Shapes Module Level 1で、MDNに`shape-outside`と`shape-image-threshold`の解説がある。
出典: https://developer.mozilla.org/en-US/docs/Web/CSS/shape-outside / https://www.w3.org/TR/css-shapes-1/

### <a id="card-2"></a>🔍 リモコンの赤外線を、HDMIケーブルの中の1本線で置き換える——HDMI-CEC 〔move: レガシー/既存機能の転用 / 領域: 無線/組み込み/ハードウェア〕

**事実**: HDMIケーブルには映像・音声とは別に、全ピン中の13番ピンを使うCEC（Consumer Electronics Control）という1本線の双方向バスが通っている。機器の電源オン・入力切替・音量・リモコンのボタン転送などが、この線を介して機器同士で交わされる。TVのリモコンでレコーダーが動くのはこのためで、ほとんどの人は存在を意識しない。

**何ができる**: 13番ピンとGNDだけをマイコンに繋げば、CECメッセージの送受信ができる。ESP-01のGPIO3をHDMIの13番ピンに接続してCECを送受信した実例や、Pico向けのCECブリッジ実装がある。Linuxには`cec-gpio`というGPIOでCEC線を扱うドライバもある。赤外線リモコンの学習・発射モジュールが担っていた「TVの電源とボリューム操作」を、CECコマンド1本で置き換えられ、見通しも赤外線LEDも不要になる。

**技術の魅力**: 専用IC無しで、GPIO1本のオープンドレイン・パルス幅変調に近い形でソフトから直接叩けるのが効いている。映像ケーブルに便乗した「すでに全家庭に敷設済みの制御線」という非対称性があり、マイコン側の作業は電圧（上限3.63V）に気を付けて繋ぐだけで済む。

**本来どこで使われてるか**: 家庭用AV機器の連動操作。TVとレコーダー、サウンドバー、Raspberry PiやKodiの間で、電源連動やリモコン転送に使われている。Raspberry Piは内蔵のCEC機能をlibcec経由で使え、Kodiの「HDMI CEC」機能として実装されている。
出典: https://support.pulse-eight.com/support/solutions/articles/30000053003-cec-adapter-using-libcec-with-a-raspberry-pi / https://github.com/gkoh/pico-cec / https://kodi.wiki/view/HDMI_CEC

🔎 検索ワード: `HDMI CEC pin 13 GPIO bit-bang` / `Linux cec-gpio devicetree binding` / `libcec cec-client Raspberry Pi` / 「HDMI CEC 自作 マイコン」

### <a id="card-3"></a>💡 潮汐APIを捨て、37個のサイン波の足し算を手元で回す——潮汐推算機の調和定数 〔move: 異分野の手法移植 / 領域: ワイルドカード(海洋学史×組み込み)〕

**事実**: 潮位は、月や太陽の運行から決まる周期の違う多数のサイン波（分潮）の合計として表せる。各分潮は振幅と位相の2つの数字（調和定数）だけで決まり、観測地点ごとに固定。ケルヴィン卿の潮汐推算機は、分潮ごとの滑車を1本の紐で束ね、物理的に足し算して潮位曲線を描いた。NOAAのMachine No. 2は37分潮を合算するよう設計され、1912〜1965年の予測に使われた。

**何ができる**: 地点の調和定数（数十組の振幅・位相）をフラッシュに焼いておけば、マイコンがネットワークも外部APIもなしに、任意の日時の潮位を計算できる。ESP32とE-Inkの電池駆動の「潮の壁掛け時計」や、釣り場に置く満潮アラーム、潮位に応じて動く灯りが、年単位で再設定なしに動く。

**技術の魅力**: 100年前の機械式アナログコンピュータの中身が、そのままFOR文の足し算になる。天体の周期は未来永劫変わらないので「データを取りに行く」必要がなく、地点ごとの数十個の定数が過去の観測全部を圧縮している。

**本来どこで使われてるか**: 潮汐予測の標準手法そのもの。NOAAは推算機を1965年まで使い、現代の解析では120以上の分潮を扱う。一番大きな機械は62分潮を合算した。
出典: https://tidesandcurrents.noaa.gov/predmach.html / https://tidesandcurrents.noaa.gov/predhist.html / https://commack.math.stonybrook.edu/~tony/tides/machines.html

🔎 検索ワード: `tide predicting machine harmonic constituents` / `NOAA harmonic constants station` / `Kelvin tide predictor pulley` / 「潮汐 調和解析 分潮」
