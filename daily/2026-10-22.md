### <a id="card-1"></a>🆕 鍵を「あとから」公開するから、放送に署名なしで真正性が付く——TESLAと衛星のOSNMA 〔move: 制約の極端化 / 領域: セキュリティ/認証〕

**事実**: TESLA は、送信者と受信者が事前に秘密を共有しない放送認証の方式で、共通鍵のMACだけで成り立つ。送信者はハッシュ鎖（k_n → k_{n-1} = H(k_n) …）を作り、鎖の根元（最初に公開する値）だけを署名つきで配る。各メッセージにはまだ秘密の鍵k_iで作ったタグを付け、少し遅れて k_i を公開する。受信者は公開された鍵をハッシュして既知の鎖の値に一致するかを見れば、鍵が本物だと分かる。見落とされがちなのは、認証の根拠が「署名の重さ」ではなく「鍵が公開される前にはタグを偽造できない」という時間の非対称性にある点。

**何ができる**: 電池駆動の小さな送信機が、公開鍵署名を毎回計算せず、HMAC1回ぶんの計算量で「ブロードキャスト」に真正性を付けられる。受信側も、ゆるい時刻（鍵の公開より前にタグを受け取ったと言える程度）さえあればよい。BLE広告やLoRaの定期ビーコンに、タグ＋数周期前の鍵を載せるだけで、なりすましビーコンを弾く設計ができる。

**技術の魅力**: 「秘密を守る」のではなく「公開するタイミングを守る」ことで認証を作っている。公開鍵暗号のかわりに、時計とハッシュ鎖という安い道具だけで、1対多の認証という難しい問題を解いている。代償として認証の確定が遅れる点（受信→鍵公開までの待ち）が、設計の核心。

**本来どこで使われてるか**: 欧州の衛星測位 Galileo の OSNMA（Open Service Navigation Message Authentication）は、E1-B の航法メッセージの予備ビットに、署名つき根鍵、認証タグ、遅延公開されるTESLA鍵を載せている。受信機は外部の緩い時刻基準を要し、初回の認証済み測位までの時間が延びる、というのが運用上のコスト。2025年7月に運用開始と報じられている。ただし測距そのものは保護されず、リレー攻撃には暗号だけでは足りないとの指摘がある。
出典: https://www.gsc-europa.eu/node/7200 / https://arxiv.org/pdf/2204.11641 / https://insidegnss.com/osnma-necessary-but-not-sufficient-for-gnss-security/

### <a id="card-2"></a>🔍 ノイズを足すほどADCの桁が増える——ディザ付きオーバーサンプリング 〔move: サイドチャネル/副作用の利用 / 領域: 無線/組み込み/ハードウェア(ADC)〕

**事実**: 10ビットADCを4回読んで平均（実際は合計して1ビット右シフト）すると、条件が揃えば約11ビット相当の分解能になり、一般に 4^K 回で K ビット増える。ただし条件は「信号に、1LSB程度のノイズが乗っていること」。ノイズが全く無い静かな入力だと、何回読んでも同じ値で、平均しても桁は増えない。見落とされがちなのは、ここで必要なのが「ノイズを減らす努力」ではなく、逆に「ちょうどよいノイズ」だという点。

**何ができる**: 外付けADCなしの安価なマイコンで、温度や電池電圧をもう1〜2桁細かく読める。入力が静かすぎる場合は、GPIOのPWM出力を抵抗とコンデンサでならした小さな揺らぎ（ディザ）を入力に足す。ノイズを積極的に混ぜた後で、4倍、16倍と回数を増やして合計する。

**技術の魅力**: 量子化誤差は信号が階段の境目をまたぐ頻度として平均に現れる、という統計の裏口を使っている。精度を上げるために部品を足すのではなく、わざと不正確さを足して、時間（読み取り回数）で払う。出力のビット幅が演算の変数の幅を超えない、という注意も実装上の細部として面白い。

**本来どこで使われてるか**: Microchip AN1152 や TI の応用ノート、STM32 L0/L4 のADCのハードウェアオーバーサンプラ（AN4629）が、この手法を公式に扱っている。STのハードウェア方式は、変換を累積して右シフトまで自動で行い、CPUの介在と消費電力を下げる。
出典: https://www.st.com/resource/en/application_note/an4629-adc-hardware-oversampling-for-microcontrollers-of-the-stm32-l0-and-l4-series-stmicroelectronics.pdf / https://embdev.net/attachment/120922/AN1152_Achieving_Higher_ADC_Resolution.pdf / https://ti.com/lit/sprad55

### <a id="card-3"></a>💡 街の AM 放送を"電源"として拾う——ラジオ塔のそばで電池なしに一日一回だけ鳴くタグ 〔move: 物理現象へのピギーバック / 領域: ワイルドカード(AM放送×エナジーハーベスト)〕

**事実**: 鉱石ラジオは電源を持たず、受信した電波のエネルギーだけでイヤホンを鳴らす。つまり放送波はすでに「電力」でもある。特許出願には、鉱石ラジオ型のフロントエンドでAM/FM放送を集め、無線センサーノードの主電源にする構想が書かれている。ただし得られる電力はごく小さく、掲示板の議論では都市部で数十μW程度とも言われる（実測ではなく経験談）。

**何ができる**: 強いAM局の送信所の近くに、同調コイル、整流ダイオード、大きなコンデンサ、LTC3108のような低電圧用の収穫ICを置く。一日かけて貯めた電気で、マイコンが数ミリ秒だけ起きて短い信号を1回送って寝る。電池の無い、日に1回だけ鳴く気象タグや「ここにいる」ビーコンになる。

**技術の魅力**: 誰も自分のために送っていない巨大な電波網に、受信コイルだけでぶら下がる発想。AM局は出力が大きく、常に出ている公共インフラで、何も契約せずに"便乗"できる。難所は、出力の小ささを前提に「起動回数」を設計に取り込むこと。連続動作は捨て、貯めて、一瞬使う。

**本来どこで使われてるか**: 実用規模の例というより研究・特許の領域で、実測ベースの設計は限られる。近い実用技術は RFID/NFC のパッシブタグで、リーダーが出す電波を整流してICを動かす。放送波を電源にする場合、送信所からの距離と同調の質が出力をほぼ決める。
