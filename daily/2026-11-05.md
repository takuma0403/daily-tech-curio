### <a id="card-1"></a>🆕 盗まれたことを、盗まれた側が知る——ハニーワードは「偽の正解」をパスワードファイルに混ぜる 〔move: 異分野の手法移植 / 領域: セキュリティ/認証〕

**事実**: パスワードDBの漏洩は、ハッシュ化していても「漏れたこと自体」に気づけないのが厄介な点だ。2013年のJuelsとRivestの論文「Honeywords」は、ハニーポット（おとり）の発想をパスワードファイルに移植した。各ユーザーに本物1つ＋偽物（honeyword）を数個〜十数個登録し、全部をハッシュ化して並べる。どれが本物かは、別系統の小さな「ハニーチェッカー」だけが番号で知っている。

**何ができる**: 攻撃者がファイルを盗んでクラックすると、候補が複数出る。当てずっぽうで1つ選んで入力すると、本物の確率は1/(k+1)しかない。偽物でログインしようとした瞬間、チェッカーが「それは偽の番号だ」と気づき、アラートを上げたりアカウントを凍結したりできる。つまり「パスワードが破られた」ことが、ログイン試行1回で検知できる。

**技術の魅力**: 守りの定番は「破られにくくする」ことだが、これは「破られたらバレる」へ守りの軸をずらしている。しかも偽物の作り方に工夫がある。偽物を「本物の数字の部分だけ差し替える」（tweaking）方式にすると、人間が付けた癖を保ったまま、見分けのつかない偽物が量産できる。ランダムすぎる偽物は逆に浮くので、偽物の“それっぽさ”の設計が肝になる。

**本来どこで使われてるか**: 学術提案としての知名度が高く、実運用ではパスワード漏洩検知の研究や、ハニーチェッカーを別サーバーに分離する設計の参考にされている。派生のHoneyEncryption（Juels-Ristenpart）は、誤った鍵で復号しても「もっともらしい偽の平文」が出る暗号で、総当たりしても正解を確認できないようにする。
出典: https://people.csail.mit.edu/rivest/pubs/JR13.pdf / https://en.wikipedia.org/wiki/Honeypot_(computing)

### <a id="card-2"></a>🔍 消せる「見たことある？」——Cuckoo filterで、削除も同期できる指紋の袋を作る 〔move: 制約の極端化 / 領域: データ/同期/ストレージ〕

**事実**: Bloom filterは「たぶんある／確実にない」を数ビットで答える便利な袋だが、1つ入れたら消せない。Cuckoo filter（Fan他, CoNEXT 2014）は要素そのものではなく数ビットの指紋（fingerprint）だけをバケットに置き、2か所の候補位置を `i2 = i1 XOR hash(指紋)` で結ぶ。この式のおかげで、指紋だけ持っていれば元のキーなしに相方の位置が計算でき、追い出し（cuckoo的な玉突き）や削除ができる。

**何ができる**: たとえばオフラインのブラウザ拡張で「もう読んだURL」を数十KBの袋に持たせ、読み返したら削除できる。さらに端末間で袋そのものを送り合い、片方が「読んだ」を消した＝未読に戻したことを反映する、といった“サーバーなしの既読管理”が作れる。偽陽性は数%以下に調整でき、容量が約95%まで詰まっても動く。

**技術の魅力**: 「元のキーを捨てたのに、削除ができる」という一見矛盾した性質が、XORの対称性ひとつで成立している点が効いている。Bloomは削除のためにカウンタ付き（Counting Bloom）にすると数倍太るが、こちらは指紋を消すだけで済む。ただし同じ指紋を重複挿入して消す運用には注意が要り、制約を理解して使う“尖った道具”でもある。

**本来どこで使われてるか**: ネットワーク機器のフロー表やキャッシュの存在判定など、メモリが逼迫する高速パス向けの研究から広まった。実装はRedis Stack（RedisBloom）にCuckoo filterとして入っており、大量のキーの「ありそう」判定を省メモリで行う用途に使われる。
出典: https://www.cs.cmu.edu/~dga/papers/cuckoo-conext2014.pdf / https://redis.io/docs/latest/develop/data-types/probabilistic/cuckoo-filter/

### <a id="card-3"></a>💡 自分自身を書き出すプログラム——クワインを「保存ボタン」にして、サーバーなしで育つ1ファイルを作る 〔move: 制約の極端化 / 領域: ワイルドカード〕

**事実**: クワイン（quine）は、実行すると自分自身のソースコードをそのまま出力するプログラムだ。ファイルを読まずに作るのが決まりで、「データ部分」と「そのデータを使って全体を再構築する部分」を二重に持つ構造になる。名前は論理学者W.V.O.クワインに由来し、再帰定理（クリーネ）で、どんな言語でも原理的に書けることが保証されている。

**何ができる**: HTMLを1枚のクワインにすると、画面の「保存」ボタンが、今のメモや設定を中に埋め込んだ“新しい自分自身”を生成してダウンロードさせられる。次に開いたファイルは前回の状態を最初から含んでいるので、DBも同期サーバーもなく、ファイルそのものが記憶になる。メールで送れば、状態ごと相手に渡る。

**技術の魅力**: 「ファイルが状態を持つ」のではなく「ファイルが、状態を持つ次のファイルを産む」と見ると、サーバーのいらない永続化の形が見えてくる。TiddlyWikiの単一HTML運用の系譜にいながら、それを理屈の上で最小の形（自己再生産）に煮詰めたものになる。バージョンが世代として並ぶので、バックアップ＝ファイルをとっておくだけ、にもなる。

**本来どこで使われてるか**: 遊びとして有名だが、実用の近縁もある。TiddlyWikiは単一HTMLに全データを抱えて保存時に自分を書き出す個人用Wikiとして広く使われ、プログラミングコンテストでは「Quine Relay」のように言語をまたぐ連鎖が披露される。
出典: https://en.wikipedia.org/wiki/Quine_(computing) / https://tiddlywiki.com/ / https://github.com/mame/quine-relay
