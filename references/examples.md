# 良い例（目標温度のお手本）

このスキルが目指すカードの温度・文体・厚み。新規生成はこのレベルに合わせる。
ポイント: 見出しはキャッチー / 本文は説明調 / 「本来どこで」で現実の凄みを乗せる / 🔎は英語固有名詞＋日本語。

### 🆕 グリッドの鼓動で“いつ撮ったか”を暴く 〔move: サイドチャネル / 領域: 電力〕

**事実**: 電力網の周波数は50Hz（or 60Hz）ちょうどで安定しているわけではなく、発電量と消費量のせめぎ合いで秒ごとに微妙に揺れている。重要なのは、この揺れ方が同じ送電網の中なら全域で同期していること（ロンドンでもグラスゴーでも同じ瞬間の指紋は一致する）。そしてこの揺れは、コンセントに繋がった機器やマイクが拾う電源ハム・蛍光灯のちらつきとして、録音・録画に勝手に焼き込まれる。これが ENF（Electric Network Frequency）。

**何ができる**: あらかじめ電力網の周波数変動を秒単位で記録し続けてDB化しておけば、後から持ち込まれた音声・動画のハムを抽出して照合し、「いつ録られたか」を秒単位で特定できる。さらに編集で別日の音が継ぎ足されていれば周波数の流れに不連続が出るので、改竄や切り貼りも検出できる。電池駆動の機器でも、近くの送電網の影響を拾うので逃げられない。

**技術の魅力**: 意図して仕込む電子透かしと違い、これは誰も埋め込んでいないのに勝手に入っている透かしだという点が美しい。撮影者がどんな機材を使おうと、電気のある部屋にいる限り時刻の指紋を背負わされる。録音内容そのものをいじっても、背景に潜むハムまでは整合させられない——という非対称性が効いている。

**本来どこで使われてるか**: 現場の鑑識技術。ロンドン警視庁の科学捜査ラボは照合用にイギリスの電源ハムを10年以上録り続け、1.5秒ごとに周波数偏差を記録したDBを構築している。ある銃器密売事件では、ENF解析で録音が改竄されていないことが裏付けられ、3人が計33年の実刑となる決め手の一つになった。ドイツ・バイエルン州警察は2010年から、ロンドン警視庁は2005年から記録を続けており、「ウォーターゲート以来、音声鑑識で最も重要な進展」と評された。
出典: https://en.wikipedia.org/wiki/Electrical_network_frequency_analysis / https://www.crimeandinvestigation.co.uk/articles/hidden-electrical-noise-can-catch-criminals

### 🔍 その場の機器の顔ぶれで“ここにいた”を証明する 〔move: 目的外利用 / 領域: ネットワーク〕

**事実**: WiFiに繋ぐと、周りのプリンタ・スマートTV・Chromecast・スマート家電が、頼んでもいないのに自分の存在をネットワークへ撒いている。これは mDNS / DNS-SD（Bonjour/Avahi）というゼロ設定の機器発見プロトコルの仕業で、各サービスは「インスタンス名」「サービス種別」（例: `_airplay._tcp.local`）という形で自分を名乗る。問題は、この“名乗り”の集合が場所ごとにほぼ唯一の顔ぶれになること。

**何ができる**: LANに一瞬入って機器の名乗りを集めるだけで、その空間の“機器エコシステムの指紋”が取れる。これでGPSなしの「確かにこの場所にいた」証明が作れる。GPSは座標を偽装できるが、特定のオフィスや店舗にしか存在しない機器の組み合わせは外から再現しにくい。来店スタンプラリー、現地確認の証跡、特定ネットワーク内でだけ解錠される鍵——“場所”を座標ではなく生態系で定義する発想。

**技術の魅力**: 本来「プリンタを自動で見つける」ための地味な裏方プロトコルを、位置のアンチ偽装トークンに化けさせるところが効いている。誰も認証用に設計していない情報が、たまたま偽装しづらいという理由で認証に転用できる。特別な権限もスキャンも要らず、ただネットワークに入れば向こうから名乗ってくる。

**本来どこで使われてるか**: 日常のあらゆる自動接続の土台。家庭・オフィスでのAirPrintプリンタやメディアサーバーの自動発見、スマートホーム機器同士の連携、企業ネットでのサービス発見に使われている。MacのFinderの「ネットワーク」やAirPlay、ESP32の`.local`アクセスも全部これ。一方この“晒し”はプライバシー上の弱点でもあり、公共の場に常設した追跡サーバーで人や機器を大規模に追えるとRFC 8882自身が警告している。
出典: https://www.rfc-editor.org/rfc/rfc8882.html

### 💡 フォントが文字を“演じ分ける”仕組みを悪用する 〔move: 仕様の目的外利用 / 領域: グラフィックス / レンズ: 表示とデータの分離〕

**事実**: OpenTypeフォントには GSUB（グリフ置換）という機能があり、「この文字の並びが来たら別のグリフに差し替えて表示する」ルールをフォント自身が持てる。`fi` を合字の1グリフに繋ぐ、みたいなやつ。重要なのは、置換ルールはフォント側に任意で書けること。表示される見た目を決めるのは、文字コードではなくフォントの判断になる。

**何ができる**: これを濫用すると、コピペすると“文字コード上の中身”と“画面の見た目”がズレるフォントが作れる。画面では完璧な英文に見えるのに、選択してコピーすると全く別の文字列が取れる。逆に見た目を変えずに特定の語だけ差し替える検閲フォントや、同じ平文を相手のフォント次第で別文に見せる隠し表示、OCRと人間の目を食い違わせる用途も組める。

**技術の魅力**: 暗号でもステガノでもなく、「表示」と「データ」の間に誰も疑わないレイヤー（フォント）を一枚差し込むのが新しい。普通セキュリティは通信路やファイルを疑うが、ここでは“その文字がどう描かれるか”という最終段を握る。コピペで中身が化ける挙動は「なんでそんなこと？」だが、見た目とデータの分離という一点は確かに成立している。

**本来どこで使われてるか**: 本来はタイポグラフィの品質向上のための機能。合字（fi, fl）、文脈に応じた字形の切り替え、アラビア文字やインド系文字の正しい連結表示など、世界中の言語を綺麗に組むためにGSUBは日々働いている。アイコンフォント（文字名→アイコン形に置換）も同じ仕組みの応用。つまり「並びを見て別の形に差し替える」エンジンは、すでにあなたの画面の全テキストで静かに動いている。
出典: https://learn.microsoft.com/en-us/typography/opentype/spec/gsub
